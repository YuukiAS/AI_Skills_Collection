## 3. 每个阶段必须具体做什么，不留给下一位临场设计

### S1：Clear Writing 0.6

复用当前 `design/clear-writing--single-entry-artifact-finalization` 的 Phase C 交接和已冻结候选，不开启新 Goal、不过早变更 0.6 语义。验证普通复杂解释、长科研文稿、GitHub 文本写前全文质量与实际写后回读、Codex 直接入口、保真和应保留的机器内容。

后续小修复处理新两条 TODO：普通汇报不暴露无当前读者价值的内部编号；回答不无端输出无关图片/巨大卡片/四框伪图。对照“用户明确要求按 ID 追踪”和“真正重要科研图/真实 PDF 页面必须保留”的反例。若组件由平台注入而非模型可控，则归因平台，不能用文字 Skill 宣称强制删除。

**出场条件：** 已正式安装的版本经真实正常入口证明质量，且真实目标文件/答复与审查对象一致。未知或不可达的 Web 宿主能力按原门槛处理，不降低测试要求来发布。

### S2：先验证跨插件能力调用，再实现一个独立 Artifact Curation Skill

先做两项最便宜的实测：
1. 在当前 Codex/ChatGPT 已安装环境，能否从一个主插件稳定读取并**实际消费**另一个插件的 Skill；记录触发条件、有效来源版本、失败时会发生什么。明确区别“安装”“打开 Skill 文件”“生成目标作品”。
2. 若不能强制跨插件调用，是否能由现有确定性生成器把 `artifact-curation` 的单一源快照打包进 Clear Writing 与适用领域插件，而无需用户每次手工选择？验证源内容同一且正常使用路径有效。

然后建立 `artifact-curation` 正式 Skill 源，不建顶层 Artifact Quality 插件。它只维护“元素是否有理由存在”的通用判断方法与成对样本；图片、PPT、UI、科研报告由对应领域 Skill 修改及专业复核，普通 ChatGPT 回复则与 Clear Writing 的信息选择联动。可以先在两个消费者（Clear Writing + Frontend Design）证明有效，再扩展 Presentations/Research Authoring/Scientific Visualization。

**出场条件：** 真实失败元素被移除，真正必要元素被保留；本轮编辑/文案改变后重新检查完整产物；没有多份互相漂移的规则；用户无需手动调用两个技能才能完成同一普通任务。

### S3：使 workflow-core 真正成为组合路由者

沿当前 `codex-workflow-protocol` 增加小型能力路由契约，不替换现有复杂任务执行保护。每次复杂任务：
- 从当前宿主**实际可加载**的技能/插件查主领域能力、所需共享技能、DA 是否适用，区别 required/optional；
- 根据依赖形成有界调用顺序，例如新网页：Frontend Design → Artifact Curation（内容必要性）→ Clear Writing（已决定保留的文字）→ 领域渲染复核；正式代码交付还需 DA；
- 明确每个专业输出的下一位消费者和已验证/未验证状态；
- 单一领域的小任务走单一路线，专业能力缺失时如实说明，并阻止依赖该能力的错误正式完成声明；
- 不为一个任务创建平行 Planner/Review/Control 状态，也不在 Bridge 编写第二套能力注册表。

用户只说目标时，Codex 应能在受测正常入口选择恰当组合；遇到必须由人授权安装的插件才提出最小请求。GPT 端的路由适配须单独证明，不能用 Codex 本地加载代替。

**出场条件：** 真正的用户任务中确实由模型消费必要技能，处理缺失技能和非触发对照；不只检查路由建议文件。

### S4：Reasoned Design（新增插件）

来源：`AI_Research_Toolkit` 复杂系统设计标准 + 已归档 DII 判断失稳；采用 `judgment-integrity` 和 `solution-design` 两个 Skill，不额外建需求发现、设计挑战和复杂解释三项顶级插件。

- 原始 DII 对话双向分支：只有用户施压不得随意反转；用户提交能推翻前提的依据/逻辑反例时必须正确修正；不能因为历史助理说过某事就冒充用户批准。
- Mica 设计截断回放：只给当时可得到的目标与源码，不把后来出现的按钮、安全默认值、ChatGPT 结构适配答案送入构思材料；测重大遗漏是否提前发现，而不是事后照单全收。
- 新鲜任务：冻结未知专业系统的原始目标，由独立审查检查完整用户链、失败恢复、成熟技术取舍和未解释的要求变更。
- 正确的“不知道”：可以交付未解决的关键证据和已检索范围；不因模型本轮必须有方案而捏造一个研究方向或修复方案。

**出场条件：** 无依据改口与重大遗漏明显少于基线，同时正确纠错不退化；结果对模型及宿主分别记录，不能只按自评文字判定。

### S5：Delivery Assurance 从工程上的最小可行闭环开始

**先审现有研究，再决定保留哪些实现包；禁止默认照搬全部 `da/1`/`da/2` 与七仓工程。** 专业项目已有 runner、验证器、参数/假数据来源、截图/PDF/真机和旧功能标准，优先复用。Bridge 仅提供既有身份、合法运行、钩子和回执能力。

1. **宿主事实探针（先行）**：当前使用的 Codex Desktop/CLI 等逐一验证项目/插件钩子能否受信任加载，启动前与完成时点哪个可用，是否真的能把失败反馈送回存活的原任务；取消和宿主退出怎样处理。失败立即收缩自动承诺，不先实现大公共层。
2. **独立 DA 产品边界**：DA 负责从批准目标、受影响旧功能确定验收义务、选已有验证器、识别缺失、判定最终完成。workflow-core 负责调用顺序与失败责任路由，Bridge 不解释产品质量。清理所有权前保留旧 workflow-core W1–W5 保护，迁移需验证不退化。
3. **试点一个真实仓库的冻结小任务**，使用已有验收器，至少运行：正确实现能够完成；原要求被静默降级必须失败；已接受旧功能回归失败；漏跑/空实现/假结果/错候选不能取得正式交付；失败反馈必须有真实原 Executor 消费；合法修复后重新通过。
4. **先试最薄判定层，后考虑扩展**：若只需小型本地判定代码 + 原 runner + 受信任钩子/受控发布检查，就停止加层。若当前 `da/2` 个别机制不可替代，逐项给出准确复现的反例及维护成本后再接入。
5. **跨项目再推广**：首例通过后选不同技术栈第二例；不能靠“七仓适配文件都存在”宣称全部已接入。正式版本每个已启用仓库独立验证。

**出场条件：** 真实普通受控开发入口能抓住两个核心错误（降级和退化），好例不卡死，失败由原任务合法继续；没有新增重复审核器/状态机。纯原生未受控聊天若无法保证，明确支持范围，不能说“所有 Codex 任务自动受保护”。

### S6：整合、分发、验收维护成本

- 使用 `AI Skills Maintainer` 按原仓库方式维护唯一源、`registry`、`profiles`、Marketplace 生成层、个人 ChatGPT plugin 包及版本；每个新插件/Skill 只有一个 canonical 正文。
- 以不同真实任务做集成回归：简单回答不受复杂审查污染；复杂判断有理由且一致；网页/科研作品内容取舍后专业信息不丢；正式代码改动防低配和旧功能退化。
- 分别在真正使用的 GPT 网页和 Codex 客户端验证**可发现、正确激活、跨能力消费、最终结果质量**。无法观察的宿主行为报告未证；不把 Skill 注册、打包成功当作发布通过。
- 评估净收益：用户补需求次数、用户发现显见缺陷、用户手工打开真实网站的次数、同类多轮返工、误删必要内容、DA 错误拦截、调用成本和平均交付延迟。正式阈值与未见题在运行前独立冻结。
- 只有每个目标能力的正常入口/完整成品/当前候选身份通过，才按仓库现有 release/rollback 流程发布。没有必要同时让所有插件、七仓和所有宿主进入同一个版本。

## 5. 四个不可妥协的实施原则

1. **每项能力有唯一主要 owner。** workflow-core 管调用；DA 管交付验收义务；领域管专业正确性；Artifact Curation 管内容存在理由；Clear Writing 管表达；Reasoned Design 管重大判断/设计；Bridge 管基础执行。
2. **正常用户请求必须真正走通链路。** 文档、注册、测试函数、回执文件和“计划调用”都不代替被运行宿主实际消费。未接通的功能准确报告部分或未支持。
3. **先低成本试点再铺开。** 失败样例来源真实；应成功、应失败、不应改变和证据缺失同时测试；不在看到产品答案之后换模型、换案例或悄悄放松阈值。
4. **用户不成为默认 Reviewer/测试员/安装维护员。** 真正只有用户能执行的账户、授权、登录、物理设备与新产品选择才提一个最小动作；Codex/专业插件能做的事自己做。发现架构假设不成立时及时止损，不为了保住旧设计继续堆层。

## 6. 现在的下一步与复核点

1. **继续原 Clear Writing 0.6 Phase C（最先）。** 本方案不修改原任务的发布门槛和身份。
2. 可由负责下一次 AI Skills 规划的人在此分支做一次**有界设计复核**：验证 workflow-core 的真实路由触发方式、`artifact-curation` 在插件间复用与安装的具体途径、Reasoned Design 的独立性，以及 DA/Bridge/领域检查的唯一责任；只对影响用户正常使用和技术可执行性的分歧提出改动。
3. 复核后独立准备 S2 小型真实入口试验与 S5 的宿主探针；**先得到事实，再写实现 Goal**。若这两项的正常入口无法工作，应修改承诺或选择已有有效替代，而非制造新的 MCP/客户端。
4. 各阶段原任务保留独立分支、授权、正式规范和发布节奏。实施准备和生产变更须另外获得对应的正常任务授权与专业审查。
