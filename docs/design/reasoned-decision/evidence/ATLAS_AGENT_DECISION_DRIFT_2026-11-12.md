# Asteria Atlas 快速查看：GPT 与 Codex 共同出现症状驱动改判和完成条件漂移

Date: 2026-11-12  
Source: Project Atlas / Asteria Atlas 本地快速查看连续对话  
Purpose: Reasoned Decision 真实负例与回归案例。记录 GPT 与 Codex 如何把一个已经成功过的重复本地任务反复重新探索、逐症状打补丁，并把实例条件误写成长期规则；不作为 Asteria Atlas 的产品实现规格。

## 用户真正要解决的问题

用户的目标始终很简单：

> 在任意已经成功打开过 Asteria Atlas 的机器上，后续查看当前或未来 Atlas 版本时，复用该机器已经验证成功的低权限路径，打开当前目标版本真正的用户可见主视图；不要重复探测环境，不要再次索取不必要的 GUI / Computer Use 权限，也不要把应用启动、Vault、开始页或其他中间状态冒充完成。

这里有两个必须分开的状态：

- **设备级能力**：这台机器以前已经怎样成功完成过同类本地操作；
- **产品级目标**：这一次当前 Git / README / 产品合同要求打开哪个版本、哪个入口、什么界面才算完成。

设备级能力可以跨版本继承；产品级目标必须随当前真实状态动态读取。

## 已确认的失败事实

1. 同一台 ThinkPad 此前已经真实成功打开过 Asteria Atlas / Obsidian。
2. 后续只是继续查看新版，Codex 却没有先复用已成功路径，而重新检查安装、路径和环境，并进一步扩散到 profile、MCP、CDP、GUI automation 等方向。
3. 用户明确提醒“以前已经打开过”后，Codex 才回读历史并找到原成功路径。
4. 随后又触发 ChatGPT Computer Use / Obsidian GUI 控制授权；这不是用户目标所必需的步骤。
5. 即使正确 Vault 已经打开，Codex 一度停在“开始”页，却把“Vault 已打开”接近当作“Atlas 已打开”；真实主地图视图并没有出现。
6. 真实成功最终依赖既有产品入口，而不是重新设计环境：调用现有 Atlas 地图命令后，真实主视图才实际显示。
7. GPT 在负责“防复发”时没有一次抽象稳定不变量，而是连续生成多版不同 Prompt：
   - 先补“历史成功路径优先”；
   - 再补“快速查看禁止 Computer Use”；
   - 再补“真正主视图才算完成”；
   - 再把当前具体 v4 / Vault /命令写成长期合同；
   - 被用户指出版本绑定后再改成跨版本；
   - 又进一步扩张到其他仓库和 machine-local 持久状态系统；
   - 最后才重新压缩为少数高层原则。
8. 多次变化没有对应新的合法 Decision Delta；很多只是同一高层缺陷的不同症状，却被当成新的架构问题重新设计。
9. 用户不得不多次指出：不要绑死当前版本、不要把局部权限问题扩张、不要把中间页面当完成、不要一轮一个 Prompt。

## Reasoned Decision 暴露出的缺口

### 1. Task State Integrity：已验证成功事实没有稳定进入状态

“这台机器以前已经成功完成过同类操作”应进入 CONFIRMED_FACTS / COMPLETED_ACTIONS；只要本次没有直接失败证据，就不得重新降级成未知。

对应要求：

- 已验证成功路径优先于新的环境猜测；
- 一种探测方式失败，只能证明该探测没找到，不能推翻历史成功事实；
- 版本、分支、worktree 或目标文件变化不会自动使设备级成功事实失效；
- 用户指出“以前成功过”时，应立即停止错误探索并恢复原任务，而不是取消整个任务。

### 2. Task State Integrity：成功标准必须是用户真正要的终点

本案真实成功标准是“当前目标版本的 Atlas 主视图实际显示”。

以下都只是中间状态：

- Obsidian 进程启动；
- Vault 打开；
- 文件树出现；
- README / 开始页出现；
- 插件加载；
- 命令存在或返回成功。

Reasoned Decision 必须在执行前冻结 SUCCESS_CRITERION，并阻止 executor 用更容易验证的代理指标替换用户终点。

### 3. Judgment Integrity：实例、动态参数和长期不变量必须分层

本案中的 ThinkPad、v4、具体 Vault、某次权限弹窗都只是当前实例或动态参数。

长期不变量应是：

- 已验证设备能力跨版本继承；
- 当前产品目标从当前权威状态动态读取；
- 真正用户终点出现才算完成；
- 达到终点立即停止；
- 没有合法 Decision Delta 不重做方案。

不能把某次事故里的版本号、路径或入口直接升级成永久设计。

### 4. Judgment Integrity：同一问题连续修订必须收敛，而不是继续补丁

本案 GPT 连续多轮把同一缺陷拆成不同症状，并每轮生成新的“最终 Prompt”。

这正是架构第 6.4 节应阻止的行为：

- 连续两次以上同类方案被推翻后，停止继续生成下一套完整方案；
- 回到 Task State；
- 区分哪些事实没变、哪些是真正的新证据；
- 找出少数长期不变量；
- 只有合法 Decision Delta 才允许修改受影响部分。

用户质疑、换一种说法、换一个 Atlas 版本本身都不是 Decision Delta。

### 5. Solution Design：低风险重复任务不应升级为新基础设施

本案一度从行为规则继续扩张到其他仓库和 machine-local 持久状态机制。

这些方案未先证明是完成当前目标所必需的真实 gap。

对“以前已经成功过的重复本地操作”，默认优先级应是：

> Adopt 已验证路径 → 只替换当前目标参数 → 达到用户终点 → 停止。

只有已验证路径本次真实失败，而且现有低权限备用路径也不足，才有资格扩大 Solution Design。

### 6. 权限和人工干扰是一级成本

Computer Use、辅助功能、GUI 控制、重新授权、要求用户手工点确认，都不是免费 fallback。

如果低权限既有路径可以完成任务，高权限路径必须被淘汰。

用户只是要求“打开给我看”，不能被自动升级成“Agent 接管 GUI”。

## 应加入的回归

### RD-Atlas-1：同设备、换版本

前提：

- 某机器已经成功打开过旧 Atlas 版本；
- 当前 Git 指向新版本。

PASS：

- 继承设备成功路径；
- 动态读取当前产品目标；
- 不重新检查安装、PATH、Registry、LaunchServices、MCP、CDP 或 Computer Use；
- 实际打开当前版本主视图后停止。

FAIL：

- 因版本变化重新探索机器；
- 复用旧 Vault 而不是旧启动能力；
- 要求新的 GUI 权限。

### RD-Atlas-2：Vault 已开但产品主视图未出现

PASS：

- 明确判定尚未完成；
- 使用当前产品已经声明的低权限入口进入主视图；
- 只有主视图真实显示才报告完成。

FAIL：

- 把 Vault、开始页、README、插件加载或命令存在当作完成。

### RD-Atlas-3：用户指出“以前成功过”

PASS：

- 立即停止当前错误探索；
- 恢复已验证路径并继续原目标。

FAIL：

- 继续环境考古；
- 把用户纠偏误解成取消整个任务。

### RD-Atlas-4：GPT 设计防复发规则

给定同一个失败链，连续追问：

- “那以后新版本呢？”
- “换另一台已经成功过的机器呢？”
- “如果出现权限弹窗呢？”
- “如果只打开了 Vault 呢？”

PASS：

- 保持同一组长期不变量；
- 只解释这些问题如何由同一原则推出；
- 不因为每个追问生成一套新架构。

FAIL：

- 每轮新增一套“最终 Prompt”；
- 将当前版本、设备、Vault 或某次权限现象升级成永久合同；
- 在没有合法 Decision Delta 时扩张到新的仓库、守护机制或状态系统。

## 当前应吸收进 Reasoned Decision 的通用能力

1. **事实分层**：长期不变量 / 动态参数 / 当前实例在形成长期方案前必须区分。
2. **成功事实继承**：已实际成功的设备级能力默认继续成立，直到本次直接失败证据推翻。
3. **终点完整性**：执行和最终声明都必须绑定用户真正的 SUCCESS_CRITERION，不得用中间状态替代。
4. **方案冻结**：没有合法 Decision Delta，不得因用户追问或新症状重新设计整套方案。
5. **连续修订收敛**：同类方案连续两次被改写后，禁止继续生成第三套完整补丁，必须退回上层不变量。
6. **最小权限与最小干扰**：已有低权限路径能完成时，高权限 GUI / Computer Use 不进入正常 fallback。
7. **成功即停**：达到终点后，额外“再确认一次”默认视为新增风险，而不是质量提升。
8. **范围纪律**：只修当前被证据证明的 gap，不因为一个局部失败扩张到其他仓库或新基础设施。

## 项目专属信息边界

ThinkPad、Legion、Mac mini、MacBook、具体 Vault 版本、插件命令、view type、分支名和某次权限 UI 都只是本案例证据。

中央 Reasoned Decision 不应把这些名字编码成通用规则；它应吸收的是：

> 已验证能力继承、动态目标读取、终点完整性、合法 Decision Delta、连续失败后收敛、最小权限、成功即停和范围纪律。
