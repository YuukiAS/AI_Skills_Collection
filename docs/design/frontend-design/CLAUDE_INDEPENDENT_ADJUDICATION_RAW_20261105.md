## 十条裁决

**1. Claude 直接接原始需求，能避免这场灾难吗？有条件能。**\
&#x20;你列的失败里，至少四类是流程造成的，换成我也会发生：

- 研究不进产品：制作方自己承认没把研究变成实现输入，最后从空白 CSS 自由发挥（p.217）。
- 好局部丢失：你在 BP-R15 和 BP-R08 反复称赞实现台和"浮窗可固定"（p.404、p.391），第 36 版画面里看不到（p.19，但那不是同 commit 对照）。
- 静态通过冒充真实通过：测试 21/21、零运行时错误（p.831），你看到的是"太朴素"（p.833）；回执写 COMPLETE（p.866），你问"我的要求有一条做到吗"。
- 局部批评变整体换向：你在 BM114 说"又回去了"（p.644）。

我本来会做得不同的只有三件事：

- 先给你看 2–3 个能点的真实场景，再做全量。
- 开工前把你认可和否决的原话写成一页，之后每轮对着改。
- 交付前自己渲染并看过截图。

第三件我没验证能不能做到：这里有 playwright 模块，但浏览器没确认，Obsidian 我打不开。

我自己最可能失败的地方：

- 默认走"米色衬线加圆角卡片"这种好看但通用的路（Atlas V10 就是，p.30，你只说"勉强"）。
- 自评偏松。
- 长会话丢细节。
- Blueprint 语义太重时，把时间花在语义上而不是画面上。

没有材料证明 Claude 做过这个任务（p.345 的 Claude Stage 只是计划），所以这是判断，不是证据。

**2. GPT 值不值得救？留，但不当主视觉设计者。**

  - 科学内容和论文精读。S022 纠正了"筛查≠检测""分割≠测量"这类真边界（p.264–272）。

**3. Design Assurance：压成薄检查，删掉八步。**
