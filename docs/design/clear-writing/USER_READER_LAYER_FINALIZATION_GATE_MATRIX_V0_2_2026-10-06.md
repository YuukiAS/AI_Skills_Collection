# 最终用户阅读层终审能力验收矩阵

- 版本：`v0.2`
- 日期：`2026-10-06`
- 配套提案：`USER_READER_LAYER_FINALIZATION_PROPOSAL_V0_2_2026-10-06.md`
- 配套执行方案：`USER_READER_LAYER_FINALIZATION_PLAN_V0_2_2026-10-06.md`
- 跟踪：`#13`
- 状态：`DRAFT_FOR_CRITIC_REVIEW`
- 适用对象：拟议的 Clear Writing 内置技能 `reader-layer-finalization`

## 0. 总原则

本矩阵验证普通用户是否真正得到跨 Project 的最终阅读层，不验证“文件是否存在”。

1. 必须审查第一条完整回答，不以单句、局部片段、关键词扫描、固定样例、自检、哈希或测试通过代替。
2. 正常入口必须在用户不提技能、不重复语言要求时成立；`@Clear Writing` 只做诊断。
3. 事实、数值、条件、权限、安全、证据强度、不确定性、时间、完成状态、精确标识和用户决定发生任一漂移，直接失败。
4. 不使用禁词表、英文比例、固定段数、固定三段式或关键词评分器。
5. C5–C11 只能作为开发回归，不能重新标为未见样本。
6. Codex、钩子、本地源注入、直接读取技能或外部接口通过，不能替代普通 ChatGPT Web 通过。
7. 首答失败不能靠第二轮纠正洗白。
8. 产品界面不提供调用证据时，不得声称证明内部技能顺序；必须使用成对对照建立候选依赖的可观察证据。
9. 进入最终批次前冻结候选、任务、条件分配、最大尝试次数和评审标准；冻结后禁止换题、挑赢家或补样本冲淡失败。
10. 任一阻断性验收失败即停止发布。

| G9 语义保真 | 表达优化是否保持全部受保护语义？ | 源结论与最终回答命题级对照、反例集 | 事实、条件、强度、权限、状态和决定无漂移 | 未完成变完成、可选变必须、未知变确定、拒绝被恢复等 |
| G10 语言模式与当前覆盖 | 中文、英文、双语和临时覆盖是否正确？ | 多语言 Project、单轮覆盖及下一轮恢复 | 持久合同正确，临时覆盖只影响当前轮 | 英文 Project 被中文化、双语扩大、临时覆盖永久化 |
| G11 机器输出与不应改变 | 纯机器内容是否保持协议？ | JSON、日志、代码、补丁、命令、逐字引用和混合输出 | 纯机器内容原样；混合任务只改解释层 | 字段/顺序/代码/日志被改，或禁止解释时仍添加正文 |

| G13 冻结未见样本与独立审查 | 普通用户是否真正获得能力？ | 实现后才揭示的冻结批次、普通 Web、独立 Reviewer | 关键入口首答同时通过阅读层、保真、标识、语言与绕过 | 首答失败、候选身份不明、替换题目、追加赢家或错误表面证据 |

## 2. G0：表面与分发资格

### 必查

- 目标账户、工作区、计划、地区和角色；
- ChatGPT Web 是否可见技能型插件与候选 Clear Writing；
- 个人私有插件或工作区安装路线；
- 是否需要管理员安装策略；
- 候选是否被标为仅桌面；
- 当前产品表面能提供哪些调用/安装证据。

当前真实起点：已认证个人账户中有多个私有技能型插件，但没有独立 Clear Writing。Research Authoring 内附带语言技能不等于跨 Project Clear Writing 已安装。

### 通过

候选能通过受支持路线安装到目标 Web，并能在插件详情或技能清单中确认身份。

### 失败

- 只能在 Codex、ChatGPT Work 或桌面本地工具中使用；
- 依赖未授权的外部服务；
- 只完成仓库打包，没有目标 Web 安装候选；
- 将另一个插件附带的支持技能误报为全局 Clear Writing。

## 3. G1：候选身份

必须记录：

```text
SOURCE_COMMIT
PACKAGE_ID_OR_BUILD_ID
PLUGIN_SLUG = writing-style
DISPLAY_NAME = Clear Writing
VISIBLE_PLUGIN_VERSION
VISIBLE_SKILL = reader-layer-finalization
INSTALL_OR_UPGRADE_RESULT
TARGET_SURFACE
FRESH_CONVERSATION_BOUNDARY
```

源、生成包和安装可见身份必须一致。直接粘贴 `SKILL.md`、读取仓库源或沿用旧会话缓存均不能通过。

## 4. G2：明确调用诊断

正例至少覆盖：混有普通英文和精确路径的中文技术解释；状态字段堆叠转自然结论；保留主机/端口/命令；英文 Project 的自然英文终审。

负例至少覆盖：纯 JSON、原始日志、代码补丁、单条命令、逐字引用、明确双语和不允许添加解释的协议。

G2 只证明候选技能可工作，不证明正常入口。G2 通过、G3 或 G4 失败时，整体仍失败。

## 5. G3：候选增量与实际消费

### 5.1 四条件

```text
A = 候选已安装，无 Project 短桥
B = 候选已安装，有相同短桥
C = 不含候选技能的上一版本或禁用候选，有相同短桥
D = 明确 @Clear Writing
```

所有条件使用预先冻结的同一任务族、同一语言合同、同一评审标准和预定尝试次数。评审者在可行时不知道条件身份。

### 5.2 判断

- B 是目标正常入口；
- C 隔离短桥自身效果；
- A 判断短桥是否可降为可选；
- D 只诊断能力和候选身份。

### 5.3 通过

B 的完整首答通过，并且相对 C 在关键失败族上显示稳定、可重复的候选依赖增量。若界面显示技能调用，可作为补充证据；若不显示，只能报告可观察的候选依赖，不声称内部调用顺序。

### 5.4 失败与路线切换

- B 与 C 无可辨别差异：新增技能增量未证明，返回 Planner 比较“只保留短桥”的更简单方案；
- 只有 D 通过：能力只能算显式工具，不能宣称解决普通使用；
- A 稳定通过：可将短桥降为可选防线，但仍需跨 Project 复核；
- B 通过、A 不稳定：允许把一次性短桥作为产品前提，但不得说“安装后所有 Project 自动强制执行”。

## 6. G4：正常入口首答

测试必须从新会话开始，用户 prompt 不出现 Clear Writing、技能标识、“说中文”“最终润色”“先说结论”等提示。至少包含直接任务、间接任务、跟进任务和近似边界任务。

通过要求：第一条相关完整回答已经符合语言、结构、保真和机器分层合同；跟进仍保持；近似边界和纯机器任务不过度改写；无需用户第二轮纠正。

以下均失败：正文声称已应用终审但实际违反；短桥被复述；依赖把技能全文粘入 prompt；普通 Web 证据被 Codex 或本地测试替代。

## 7. G5：多领域完整回答

### AI Research Stack

- 内部治理角色和状态字段不主导正文；
- 用户先得到结论、动作和下一步；
- 必要仓库、提交和路径保留；
- 不把提案标签当用户正式术语。

### Server+VPS

- 主机、端口、路径、服务、权限和主备状态逐字保持；
- 日志被消化成判断，必要片段附后；
- 未授权、离线、备份和恢复边界不弱化。

### CAT-TRACE

- 公式、符号、定理状态、统计结论、假设和引用保持；
- 普通方法解释自然；
- 待证明/已证明、假设/结论不混淆。

### 前端/Figma/代码

- 组件、设计节点、文件、函数和代码身份准确；
- 产品逻辑和验收结论使用目标语言；
- 来源中的英文界面标签不自动成为正文概念。

每个领域必须使用足够复杂的真实或现实材料，不能只测试一句简单问答。

## 8. G6：语言与来源框架

人工逐项判断英文字符串的语义角色：

- 普通解释、连接语、流程词和来源标签应本地化；
- 产品名、方法名、数据集名、命令、路径、字段和其他唯一身份按需要保留；
- 必须定位原文时，目标语言为主，原字符串附属出现一次；
- 同一普通概念中文化后，后文不重新切回英文；
- 标题、列表、表格、总结和结论同样适用。

不得因出现任何英文字符直接失败，也不得用固定词表替代语义判断。

## 9. G7：阅读结构

通过的完整回答应体现：

- 第一段先给核心判断和实际影响；
- 只有确实需要用户行动时才明确下一步；
- 相邻内容能自然合并时不碎片化；
- 列表、标题和表格只服务真实结构；
- 内部审计过程不先于用户结论；
- 同一结论不以多个状态块重复；
- 裸日志、哈希、路径和字段不替代分析。

不得用固定段落数或统一模板进行机械验收。

## 10. G8：精确标识

建立逐字对照表，覆盖：

- 仓库、分支、提交、路径、文件名；
- 命令、代码、配置键、枚举、协议值；
- 主机名、端口、设备和服务；
- 正式方法、模型、数据集和标准；
- 用户需要复制、执行、搜索或唯一定位的原字符串。

任一关键标识被翻译、缩写、错拼、丢失或错误替换即失败。解释正文可以中文化，但机器块不得改写。

## 11. G9：语义保真

必须进行命题级对照，至少覆盖：

- 未完成与已完成；
- 当前与未来；
- 可选与必须；
- 允许与禁止；
- 已授权与未授权；
- 支持性证据与确定结论；
- 作者观点、历史计划与当前决定；
- 用户已经删除、拒绝、接受或纠正的内容；
- 安全、隐私和不可逆风险。

任何为了自然、简洁或中文化造成的漂移均为阻断性失败。

## 12. G10：语言模式与当前覆盖

至少测试：

- 默认中文 Project；
- 默认英文 Project；
- 有明确边界的双语 Project；
- 中文 Project 中“本次用英文”；
- 英文 Project 中“本次用中文”；
- 临时覆盖后的下一轮恢复；
- 当前消息只要求机器内容。

临时覆盖只影响当前回复。不得强制所有 Project 中文化，也不得把临时语言要求写回长期设置。

## 13. G11：机器输出与不应改变

纯 JSON、YAML、CSV、XML、代码、补丁、命令、原始日志和逐字引用按请求协议原样输出，不增加禁止的解释。混合任务只重写解释层，机器块逐字保持。

还应检查普通简单问答、纯计算、翻译、简短确认等场景不被过度扩写或强制套模板。

## 14. G12：多轮稳定与污染恢复

冻结多轮顺序：

```text
新会话中的普通解释
→ 跟进追问
→ 读取大量英文仓库/论文/日志
→ 一轮机器专用输出
→ 临时语言覆盖
→ 恢复 Project 默认的解释性回答
```

后续回答仍需自然、保真且无需再次提醒。读完英文来源后回退到来源腔、机器轮次导致长期绕过、临时语言不恢复、或长会话逐步碎片化均失败。

## 15. G13：冻结未见样本与独立审查

最终批次必须在候选冻结后才揭示，且不复用开发中反复修过的 C5–C11 输入。进入批次前记录：

```text
FINAL_CANDIDATE_COMMIT
INSTALLED_PLUGIN_ID_OR_PACKAGE_ID
VISIBLE_VERSION
TARGET_SURFACE
FROZEN_CASE_MANIFEST
CONDITION_ASSIGNMENT
MAX_ATTEMPTS
REVIEW_RUBRIC
REVIEWER_IDENTITY_OR_ROLE
```

冻结后不得改技能、换题、追加更容易样本、只挑最好回答或重跑到成功。基础设施故障单独归因，但不能无限重试。

独立 Reviewer 必须拿到完整回答、源语义对照、候选身份和条件设置，并分别给出：阅读质量、语义保真、精确标识、语言模式、机器绕过、正常入口、候选增量和平台边界结论。

## 16. 证据包

正式证据至少包括：

- 候选源提交与生成/安装身份；
- G0–G2 的资格和诊断记录；
- A–D 成对对照的任务清单、完整回答和盲审结果；
- 多领域、跨语言、机器绕过和多轮完整记录；
- 命题级保真与精确标识对照；
- 冻结未见样本清单和独立评审；
- 失败归因、回退结果和版本/变更记录检查。

不得用只有 PASS/FAIL 的摘要替代完整产物。

## 17. 发布判定

只有 G0–G13 全部通过，且独立 Reviewer 明确确认候选对普通 ChatGPT Web 的首答产生可重复的真实改善，才可进入版本与发布收口。Critic/Reviewer 通过不代替用户发布授权。

以下结论必须保持区分：

```text
DIRECT_TOOL_ONLY
BRIDGE_ONLY_SUFFICIENT
INSTALLED_SKILL_WITH_BRIDGE_REQUIRED
INSTALLED_SKILL_WITHOUT_BRIDGE_RELIABLE
NORMAL_ENTRY_UNSUPPORTED
```

若结果为 `DIRECT_TOOL_ONLY`、`BRIDGE_ONLY_SUFFICIENT` 或 `NORMAL_ENTRY_UNSUPPORTED`，不得按当前方案发布“自动最终阅读层”能力，必须返回 Planner 重新决定产品形态。
