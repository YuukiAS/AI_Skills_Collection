# D7 冷读检查

依据为当前 `blueprint.json` 的内嵌设计、接口、验收条款和走查。以下判断针对执行者是否还需要设计方补作决定。蓝图的 `summary` 和空的 `versions` 表明当前仍是待审候选，实际实施须经过已经规定的冻结和授权步骤。

## 1. 拟开工顺序

1. **先完成实施前交接。** D1 收敛九项合同，对同一 `snapshot_sha256` 完成 D5 草稿档、D6、D7、D8，取得用户批准，追加冻结历史，再完成 D5 冻结档，最后写出包含三个身份的 `freeze.json`。独立 X1 实际读取、接收后，D1 完成状态写权交接。依据节点为 `contract`、`gates`、`freeze`、`writer`、`role-X1`。
2. **建立共用文件协议和运输规则。** 按唯一任务目录实现状态结构、任务书、结果、派发及事件记录，接入只读记录检查，处理预期修订号、重复返回、冲突和不明写入恢复。再将调度条件、角色读限和自包含提示词接入两个规划入口。依据节点为 `state`、`writer`、`record-check`、`dispatch`、`prompts`、`source-layout`。
3. **接通设计端完整流程。** 实现澄清分类、D2/D3 独立设计、按需 D4、D1 汇总、四关卡和批准冻结，以及小修继承、大改重审、前后告知。Blueprint 检查器接入指定的 `c05edcf51bc93f8be82180fd4ad28a250937f195`。依据节点为 `clarify`、`role-D1` 至 `role-D8`、`gates`、`q-checker`、`freeze`、`revision`、`q-inheritance`。
4. **接通交付端完整流程。** 实现 X1 接收、X2 候选提案、条件触发的 X3/X4/X5、验收资产分级与三类校准、当前候选和原始证据绑定、偏离申报、返修及五类设计退回，随后接通十三项签发核对和签发后复核撤回。同步接入三项衡量。依据节点为 `role-X1` 至 `role-X5`、`acceptance`、`calibration`、`candidate`、`evidence`、`deviation`、`sign`、`metrics`。
5. **生成插件并验证真实使用。** 从唯一源生成两个自包含包，调整为 12 个插件、32 个技能，保留原有能力。先检查结构和已知回归，再以同一最终规则版本完成 GPT 网页端、GPT Work 执行任务和安装后 Codex 入口的实际观察，覆盖完整成功链、危险坏例和缺证例。依据节点为 `minimum`、`source-layout`、`planning-entry`、`execution-package`、`q-capacity`、`capability-check`。

其中第 2 至第 5 步遵循 `minimum.terminal.mechanism` 规定的四个内部工作包顺序。

三个内容身份的算法也已有定义。`snapshot_sha256` 使用规定的 `snapshotOf` 内容，`semantic_hash` 从同一内容快照只删除列明字段，两者都使用 JCS 规范化字节。`brief_sha256` 覆盖整个任务书对象并使用相同规范化规则。`bundle_sha256` 使用冻结输出文件的原始字节。

- `sign`、`evidence`、`state` 已明确整份签发、声明暂停、维持或撤回、证据失效和重新签发的处理。
