# D8 读者复述：第 4 轮（合批）

开一个全新的 GPT 对话，推理强度调到最高，把 `---` 下面的全部内容贴进去。

---

你是一位读者，帮忙检查一组说明文字能不能被人读懂。你此前没有看过这个项目的任何材料。

项目一句话简介：这是一套给 AI 协作用的插件流程：先把需求设计成一份可冻结的蓝图，再按冻结的蓝图交付成品，并由负责人核对证据后签发。

下面有 3 个单位，每个单位是流程中某一步的说明，顺序已经随机打乱。请逐个处理，并遵守两条规则：
- **每个单位只依据它自己的文字理解。** 不要用其他单位的内容补全信息，也不要猜测前后步骤。
- 不要读取任何仓库文件或网页。

对每个单位，用你自己的话分五点复述：
1. 这一步在做什么；
2. 它拿到什么；
3. 它交出什么；
4. 为什么要这样做；
5. 出错时会怎样。

然后列出读不懂或拿不准的地方：哪个词或哪句话，困惑是什么。不要评价文字好坏，也不要提修改建议。

## 写回

把结果写到 GitHub 仓库 `YuukiAS/AI_Skills_Collection` 的分支 `gates/assurance-0.1-d1`，文件路径为 `docs/design/assurance/plugin-0.1-d1/gates/d8/round4/RESULT.json`。文件内容是一个 JSON 数组，每个单位一项，字段如下：

```json
[{"subjectId": "<单位编号>", "round": 4, "paraphrase": "<五点复述>", "confusions": ["<每条一个，没有就留空数组>"]}]
```

另在数组外层不要加任何内容。只写这一个文件，不要读取、修改或删除仓库里的其他文件，不要切换分支。提交后回读确认。如果没有写入权限，就把 JSON 直接回复在对话里。

最后用一两句中文说明：写入是否成功，有多少个单位存在读不懂的地方。

## 单位

### 单位 1（编号 `fail-web-method-step-1`，类别：失败处理）

```text
这一步：申报网页端打包偏离
这一步在做什么：实现者找不到或无法复现用户已测通的网页端打包方法时，把实际结果作为偏离交给交付负责人。
拿到什么：拿到仓库及实际包中已查找的来源和复现结果，注明找不到或无法复现的部分。
交出什么：交付负责人收到偏离和原始事实，不把这部分记为完成，也不由实现者另造打包方式。
为什么要这样：已定方案是复用用户测通的方法，不能因为找不到就换一套方案并声称满足要求。
出错会怎样：仍找不到或无法复现时保留缺口，交付负责人按既有偏离流程处理。
```

### 单位 2（编号 `wi-web`，类别：正常走查）

```text
这一步：在网页端验收规划包
这一步在做什么：专项检查者在真实的 ChatGPT 网页端上传包并新开对话，读取规划正文、至少一张角色卡和一份模板。再依据公开安全的示例任务状态生成下一条完整提示词，并按要求写回指定分支，无写权限时如实给出内容。
拿到什么：拿到来自同一规则源的两规划入口包、公开安全的示例任务状态和实际仓库权限。
交出什么：得到三件事的原始对话记录，由交付负责人判断是否签发；只上传成功不算通过。
为什么要这样：网页端没有本地终端，不能以本地安装或上传成功代替实际读取、生成和写回的验证。
出错会怎样：找不到或无法复现既有打包方法时，由实现者把实际偏离交给交付负责人，不另造打包方式；缺写权限时给出内容并记录实际边界。
```
