## 补充（D1，回应 Codex 交回的术语事项）

“检查器”有两种不同的对象，必须分开写：
- 检查设计文件的，写“Blueprint 检查器”；
- 检查成品是否达标的，写“验收检查程序（检查器）”。

`wr-calibration` 里的“检查器”属于后者。

| 原词 | 第一次出现时写成 |
|---|---|
| 检查器（验收用） | 验收检查程序（检查器，用来判定成品是否达标的程序） |
| 固定源提交 | 固定的源仓库提交（指定的版本，读取规则时不随最新改动变化） |
| 包根、资源根 | 插件包的根目录（安装后包内文件的起点） |
| 复制映射 | 复制映射（生成插件包时，哪些源文件复制到包内哪个位置的对照表） |
| 生成器 | 插件包生成器（仓库里把源技能打包成插件的脚本） |
| 校准 | 校准（用答案已知的样例试运行检查程序，确认它给出正确判定） |
| 控制例 | 控制例（答案已知的样例：应通过的正例、应失败的坏例、应判“无法判断”的缺证例） |
| 默认验收实现 | 实现者默认同时写好的验收检查程序 |

| 冻结档 | 冻结档检查（Blueprint 检查器中要求已有版本历史的严格模式） |
