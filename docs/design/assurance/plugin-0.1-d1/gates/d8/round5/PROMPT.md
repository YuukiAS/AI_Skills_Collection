# D8 读者复述：第 5 轮（合批）

开一个全新的 GPT 对话，推理强度调到最高，把 `---` 下面的全部内容贴进去。

---

你是一位读者，帮忙检查一组说明文字能不能被人读懂。你此前没有看过这个项目的任何材料。

项目一句话简介：这是一套给 AI 协作用的插件流程：先把需求设计成一份可冻结的蓝图，再按冻结的蓝图交付成品，并由负责人核对证据后签发。

下面有 4 个单位，每个单位是流程中某一步的说明，顺序已经随机打乱。请逐个处理，并遵守两条规则：
- **每个单位只依据它自己的文字理解。** 不要用其他单位的内容补全信息，也不要猜测前后步骤。
- 不要读取任何仓库文件或网页。

对每个单位，用你自己的话分五点复述：
1. 这一步在做什么；
2. 它拿到什么；
3. 它交出什么；
4. 为什么要这样做；
5. 出错时会怎样。

然后列出读不懂或拿不准的地方：哪个词或哪句话，困惑是什么。不要评价文字好坏，也不要提修改建议。

## 写回

把结果写到 GitHub 仓库 `YuukiAS/AI_Skills_Collection` 的分支 `gates/assurance-0.1-d1`，文件路径为 `docs/design/assurance/plugin-0.1-d1/gates/d8/round5/RESULT.json`。文件内容是一个 JSON 数组，每个单位一项，字段如下：

```json
[{"subjectId": "<单位编号>", "round": 5, "paraphrase": "<五点复述>", "confusions": ["<每条一个，没有就留空数组>"]}]
```

另在数组外层不要加任何内容。只写这一个文件，不要读取、修改或删除仓库里的其他文件，不要切换分支。提交后回读确认。如果没有写入权限，就把 JSON 直接回复在对话里。

最后用一两句中文说明：写入是否成功，有多少个单位存在读不懂的地方。

## 单位

### 单位 1（编号 `fail-freeze-explanation-whole`，类别：失败情形整体收场）

```text
这一步：冻结说明缺口的收场
这一步在做什么：用户追问角色对照设计检查冻结说明，发现影响用户决定的内容漏写、增加未承诺内容、验收器数量分类不一致或大件下载遗漏时，交回设计负责人改写。
拿到什么：拿到按固定格式写的冻结说明和同一份受审设计。
交出什么：设计负责人收到具体缺口，按固定骨架改写；冻结前再把说明和设计一起交给用户追问角色检查。
为什么要这样：冻结说明是用户批准前唯一要读的东西，漏写会使用户在没看到的情况下批准。
出错会怎样：问题未解决时保持缺口，交回设计负责人，不把说明已经通过检查写进记录。
```

### 单位 3（编号 `wr-gates`，类别：正常走查）

```text
这一步：完成四道冻结关卡（结构检查、用户代理追问、冷读、读者复述）
这一步在做什么：负责人在冻结前用草稿检查（Blueprint 检查器中不要求已有版本历史的模式）检查结构，并收集同一设计上的追问、冷读和复述。用户追问角色还要把冻结说明和设计对照，检查漏写、多写、验收器数量分类和大件下载遗漏。
拿到什么：拿到同一内容快照（设计文件除版本历史以外全部内容的哈希）的四项关卡结果、读者复述关卡（D8）本轮新 GPT 对话的逐单位复述，以及记录中的读者隔离字段 `reader_isolation`（合批时取值 `single-thread-batch`）。
交出什么：设计负责人逐项比对原意与复述，全部正确时本轮合批就是有效通过，不另设单位例外。读错则改写，下一轮新对话只重读改动及与改写单位属于同一步骤或同一失败路径的单位。
为什么要这样：每轮新对话合批降低逐步换人的独立性，但这是用户为可操作性接受的取舍，冻结说明要如实写明。
出错会怎样：有单位读错就改写后进入下一轮新 GPT 对话，不复用旧文字或旧对话的通过记录。
```

### 单位 4（编号 `wr-freeze`，类别：正常走查）

```text
这一步：批准具体设计
这一步在做什么：设计负责人先按固定十节骨架给用户冻结说明，说明已由用户追问角色对照设计检查漏写、多写、验收器数量分类和大件下载。用户先批准四道冻结关卡（结构检查、用户代理追问、冷读、读者复述）共同通过的内容快照（设计文件除版本历史以外全部内容的哈希），再用Blueprint 的冻结命令（给设计文件追加一条版本历史）追加首个版本。
拿到什么：拿到按固定格式写成并经用户追问检查的冻结说明、获批快照、四项有效关卡结果、用户答复和追加一条版本历史（内容快照本身不变）后的完整文件；读者复述关卡（D8） 合批已经设计负责人逐项判断正确。
交出什么：对完整输出运行冻结档检查（Blueprint 检查器中要求已有版本历史的严格模式），核对获批快照未变后才写冻结记录，同时保存内容快照、语义定义和完整文件的三个哈希（内容快照、语义、完整文件）。
为什么要这样：追加历史不改变获批内容时，原关卡和批准继续有效；冻结档复验只是机械确认，不需要重新批准。
出错会怎样：D8 尚未判断全部正确时先改写并下一轮重读；冻结档不通过或快照改变则不写冻结记录，交回设计负责人。冻结说明有漏写或多写等缺口时，交回设计负责人按固定格式改写。
```
