# D6 用户代理追问第 12 轮：冻结说明对照结果

阻塞问题总数：**8**。

## 阻塞问题

1. **交付角色责任披露不等价。** 第 1 节把 X1 写成“会按这份设计做出两个插件”，而 Blueprint 明确 X1 不写产品或验收代码；X2 是默认实现者，并默认编写验收实现，X1 负责组织、审定验收资产、亲读证据和唯一签发，X3 只在规定条件下独立编写验收实现。当前说明会让用户误解实现和验收独立性。关闭条件：按 Blueprint 明确 X1/X2/X3 的责任边界，并消除第 1 节与第 8 节的责任歧义。

2. **独立角色的会话隔离与不可用处理披露不完整。** Blueprint 固定了 D2/D3 每次独立设计新开、D6 每轮新开且不继承负责人上下文、D7 每轮新开且只读 Blueprint 与无设计暗示运输说明、X3 首次独立新开且不继承 X2 解题过程、X5 每次独立裁判新开且不看实现过程，以及 X2/X4 的沿用规则；没有满足档次/独立性/工具能力的入口时不得降档或由负责人冒充。说明只完整讲了 D8，其他角色只讲档次。关闭条件：把这些会改变独立性和用户转交方式的会话规则用用户可读语言补全。

3. **小修继承批准规则被写弱且漏掉关键边界。** Blueprint 要求精确的身份相等或完整合格小修继承链，由 D1 分类；原批准与 D6–D8 记录按原范围继承，语义版本不变，继承记录完成后新值才成为有效冻结对象；多次小修按累计差异重判，不能拆单规避。说明用“语义内容可证明不变”替代精确身份条件，也没披露决定者、继承效果、累计差异和生效时点。关闭条件：恢复与 Blueprint 等价的批准继承语义。

4. **状态恢复漏了一种必须交用户决定的情况。** 当 git 历史里一个有效的 STATE.json 都找不到时，Blueprint 禁止自动重建，负责人必须列出现存不可变记录，交用户确认后再初始化；说明未披露。关闭条件：在恢复边界中加入这一情形。

5. **签发维持/撤回的判据和后果披露不足。** 说明只说 X1“决定维持还是撤回”，Blueprint 要求 X1 按原冻结标准复核；复核期间保留原签发引用，撤回后清空当前引用、使被推翻证据失效、进入返修或规定设计退回，新签发取代旧签发但旧记录永久保留。关闭条件：写清复核依据及维持/撤回后的状态和历史语义。

6. **回归用例概括与正式固定输入冲突。** 正式 R1–R7、S1 表与 Blueprint 逐字一致，但前面的概括说“每个用例……用公开的示例任务（给一个小命令行工具加导出功能）”。R4、R6、R7、S1 等实际输入并不是这个任务。关闭条件：删除该泛化或改成“使用公开安全的固定输入，具体逐项见正式定义”。

7. **依赖披露不完整、固定检查器身份不精确。** Blueprint 固定使用 Asteria-Blueprint 检查器提交 `c05edcf51bc93f8be82180fd4ad28a250937f195`，正式实施还必须加载既有 `workflow-core` 与 `ai-skills-core`；说明只写“固定版本的 Blueprint 检查器”且漏掉两个既有维护插件依赖。关闭条件：补齐准确依赖身份；大小没有设计记录的继续明确为未知，并保持首次实际下载/安装前测量、单项超过 100 MB 先由用户决定。

8. **0.1 的残余能力边界完全漏写。** Blueprint 明确不承诺所有复杂任务不再出现设计缺口、不承诺独立模型不会误判、不承诺纯文件权限能阻止有写权限的人篡改；当前“这次不做的”只列延后功能。关闭条件：把这些会影响预期和批准决定的非保证边界写入冻结说明。

## 非阻塞问题

1. 第 3 节“你自己怎么验……拦住了才算通过”容易读成新增的用户端到端必跑验收；正式责任其实由 X1 组织和判定，只有冻结合同明确规定的用户验收才是签发前提。建议明确这是用户可选的独立抽查。
2. 第 2 节“前四条是你之前明说过的，后面几条是设计者替你定的默认做法”来源归因不准确：市场 12/32 在 Blueprint 中明确是用户已裁决决定，后文 X1=GPT Work 极高也明确是用户决定。具体行为写对，故不阻塞。
3. 第 3 节把首次冻结简化成“四关卡 → 用户批准 → 交付”，没有告诉用户批准后还有追加首版、D5 冻结档核对获批快照未变、再写冻结记录的机械保护。它不改变批准对象，故列为非阻塞精度问题。

## 4. 单项超过 100 MB 的下载或安装

Blueprint 中实施/验收明确涉及的资源包括：

- Python 3.10 或更新的受支持版本；
- `jsonschema[format-nongpl]==4.26.0`；
- Python `rfc8785`，版本在实施时固定；
- JavaScript `canonicalize`，版本在实施时固定；
- Asteria-Blueprint 检查器固定提交 `c05edcf51bc93f8be82180fd4ad28a250937f195`；
- 仓库现有市场生成器；
- 正式实施必须加载的既有 `workflow-core` 与 `ai-skills-core`；
- thread handoff、thread instruction 已测通插件包的方法和工具，X2 定位来源后复用；

- 真实验收所需 Claude Code、GPT Work、Codex、ChatGPT 网页端环境。

Blueprint **没有记录上述任何单项的下载/安装大小**，因此不能断言任何一项低于或高于 100 MB。冻结说明对此的总原则正确：第一次实际下载或安装任何依赖前先记录实际大小，单项超过 100 MB 必须先由用户决定；它也没有错误声称“小于 100 MB”。
