# D6 用户代理追问第 7 轮结果

阻塞缺口共 **5 条**。

第一条位于 Blueprint 的 `freeze` 节点：Blueprint 要求 D6 在用户批准前对照检查冻结说明，但没有给冻结说明定义内容身份，也没有要求 D6 结果、用户批准或 `freeze.json` 核对同一份说明。当前批准对象只绑定 Blueprint 的 `snapshot_sha256`。因此如果冻结说明在 D6 检查后被修改或替换，现有合同无法唯一证明用户最终看到的仍是 D6 检查过的版本。用户会在“这份批准说明到底是否经过 D6 对照检查”这一点上失去可靠验收链。由 D1 关闭：为冻结说明建立可回读的内容身份，并要求 D6 结果、用户批准前展示及冻结记录核对同一身份；说明变化后原 D6 说明检查失效并重新检查。

第二条位于 `FREEZE_EXPLANATION` 的规划角色说明。说明写“规划端角色都在 GPT 上跑，每个角色每轮只转交一次”，而 Blueprint 的 `r-dispatch`、`role-D1`、`role-X1` 和 `planning-entry` 明确只有 D2、D3、D6、D8、X5 属于用户手动转交到 GPT 网页端的角色；D1、X1 明确不在此列，由 Claude 或 GPT Pro 担任长期负责人。说明后文又写本插件 D1 由 Claude 担任，前后不能唯一解释。用户会误解自己需要转交哪些角色以及 D1/X1 的运行位置。由 D1 把这段改成与 Blueprint 唯一一致的角色范围后关闭。

第三条位于 `FREEZE_EXPLANATION` 的状态恢复说明。Blueprint 的 `state.terminal.mechanism` 和 `fail-recovery.handling` 规定：涉及冻结、批准、签发、撤回的恢复冲突都交用户；普通冲突若固定保守处置无法安全实行，也交用户，其中明确包括原派发已有写入与重新派发互相冲突，以及重新派发会产生不可撤回外部后果。冻结说明漏掉“撤回”和“已有写入与重新派发冲突”，并把普通冲突的用户介入条件缩成只有不可撤回后果。用户会低估恢复时需要自己决定的范围。由 D1 补全这些情形后关闭。

第四条位于 `FREEZE_EXPLANATION` 的验收说明。67 个验收器的数量和六类分类本身正确，但说明在列出少数真实宿主或专业判断后写“其余检查读文件、跑脚本就能完成”。实际 Blueprint 中 48 个验收器的 `environment` 为 `real`，全部 67 个的 `runner` 都是 `one-human-action`；角色执行、冻结关卡、交付证据、恢复等多项验收要求真实派发、真实观察或负责人亲读。用户会低估验收实际需要的运行和人工证据。由 D1 按 Blueprint 的真实执行条件改写这段后关闭。

第五条位于 `FREEZE_EXPLANATION` 的下载与安装说明。Blueprint 能确认正常路径会用到 `jsonschema[format-nongpl] 4.26.0`、Python `rfc8785`、JavaScript `canonicalize`、Python 3.10+、固定提交的 Asteria-Blueprint 检查器，以及既有网页端打包方法/包等资源，但没有给这些依赖、运行时或插件包提供体积上限或实测大小，且两个哈希库的版本留到实施时固定。因此 Blueprint 不能支持“没有超过 100 MB 的下载或安装”以及“三个库都不到几 MB”的确定承诺。用户会在资源边界未经证据支持的情况下批准。由 D1 补足可验证的大小与安装前提，或把说明改成 Blueprint 实际能支持的未知边界后关闭。

## 冻结说明四项核对

**漏写：有。** 状态恢复中必须交用户决定的情形漏写了“撤回冲突”和“固定保守处置无法安全实行、包括原派发已有写入与重新派发冲突”的情况。

**多写：有。** “规划端角色都在 GPT 上跑”比 Blueprint 的角色范围更宽；“其余检查读文件、跑脚本就能完成”比 Blueprint 的实际验收要求更弱；“没有超过 100 MB”“三个库都不到几 MB”没有 Blueprint 中的大小证据支持。

**验收器数量和分类：数量及六类分类正确。** 我直接从全部节点及子节点的 `validators` 数组重新统计，共 67 个，全部带有 `id`、`name`、`oracle`，没有把 `terminal.acceptance` 的文字当独立验收器。67 个中正常验收器 54 个、失败路径验收器 13 个；六类分别为：任务状态与交接 8、派发与提示词 3、13 个角色职责 15、从需求到冻结 18、从冻结到签发 13、打包与安装 10。每个验收器恰好进入一类，无漏项、无重复。需要修正的是冻结说明对这些验收器“怎样实际执行”的概括，不是数量和六类计数。

**大件下载说明与 Blueprint 不一致。** Blueprint 没有足够的大小证据支持“没有单项超过 100 MB”的确定判断；因此这一句目前不能通过 D6 对照检查。它并不证明实际一定存在超过 100 MB 的下载，只证明现有 Blueprint 无法支持冻结说明的确定承诺。

附录中的 Blueprint 文件 SHA-256 与固定提交实际内容一致；按 Blueprint 自己定义的 JCS 规则重新计算的 `snapshot_sha256` 也与冻结说明附录一致。这两项身份信息没有发现错误。
