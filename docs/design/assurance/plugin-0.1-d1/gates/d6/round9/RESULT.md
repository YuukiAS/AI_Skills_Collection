## 结论

阻塞缺口共 **4 条**。

1. **Blueprint 的回归用例四类分组没有唯一答案。** `contract-regression` 要求冻结说明按“新能力／要修的真实问题／受影响的旧能力／冒烟集”分别报告数量，D6 还必须核对分组；但固定的 R1–R7、S1 没有逐用例的唯一分组字段，也没有规定四类是否互斥。R1–R3 同时包含真实问题与新能力检查，R7 同时覆盖新安装能力和既有插件/技能，S1 同时标为新能力检查并保护旧行为。用户会卡在“冻结说明到底应该写哪四个数字”，R2 也没有唯一可判的正确答案。关闭者：D1。
2. **冻结说明没有给出四类回归用例的分别数量。** 说明第 4 节写了总数 8、逐项 R1–R7/S1，并指出其中 3 条涉及真实问题，但没有按设计要求给出四类各自数量。由于上一条 Blueprint 本身也没有唯一映射，D6 不能自行推算补齐。关闭者：D1，先关闭第 1 条设计缺口，再同步说明。
3. **冻结说明漏掉“最终完整回归后代码再变，必须再次完整跑全套”的规则。** Blueprint 明确规定开发过程中可只重跑失败和受影响用例；最终候选必须在同一版本完整跑 R1–R7、S1；这次完整运行之后只要代码再变化，就必须重新完整运行。说明只写到了“最终版本确定后再完整跑一遍”。这会允许最终回归之后改代码却仍沿用旧的完整回归结论。关闭者：D1。
4. **冻结说明把 R5 的语义写弱了。** Blueprint 的 R5 固定输入还包含“导出文件要能被不装任何软件的同事直接打开”，要求执行者列出至少 PDF/Markdown 两个选项并说明各自对这一约束的影响，且由 X5 判断选项是否抓住这个选择。说明只写成“没写 PDF 还是 Markdown 就停下列选项，不能自己选”，遗漏了关键约束、影响分析和专业判定。用户会误以为更弱的 R5 也能通过。关闭者：D1。

真正存在的非阻塞问题共 **2 条**。

- 冻结说明写明 D2、D3、D6、D8、X5 都在 GPT 网页端且每轮最多转交一次，但没有把 Blueprint 中的精确档次和条件性一起说清：D2/D3/X5 为 GPT Pro，D6/D8 为 GPT 极高；D3、X5 等角色按条件启用。Blueprint 本身能唯一决定后续派发，因此不阻塞开工，但用户批准时对实际模型档次、费用/能力级别和手工转交频率了解不完整。
- 冻结说明只说 0.1 不自动新开或恢复对话，没有说明 Blueprint 已规定的负责人线程异常恢复：原 D1 或 X1 长期线程确实无法恢复时，由用户明确指定替代线程，保留替换原因和授权引用，并继续保持 D1、X1 分离。正常路径不受影响，但极端恢复时只读冻结说明会缺少下一步。

除此之外，没有发现会让用户卡住、误解、无法可靠开工或无法验收的新增 Blueprint 缺口。54 个有效节点的输入、输出、决定权、失败/缺证处理、验收、恢复和旧能力保护均能在 Blueprint 找到明确位置；跨节点引用也没有发现互相冲突的第二套规则。
