## 2. 你这次在做的决定

批准就等于同意以下取舍。前四条是你之前明说过的，后面几条是设计者替你定的默认做法。

- **需要你手动转交的角色（D2、D3、D6、D8、X5）都在 GPT 网页端跑，每个角色每轮只转交一次。** 代价是你每轮要手动发几条，但不会再有一次发几十条的情况。负责人 D1、X1 不在此列，由 Claude 或 GPT Pro 担任，各自用一个长期对话；执行角色在哪里跑按各自档次：D4、D5、D7 和 X2 的普通实现由 Codex 跑，Claude 当负责人时直接派发，GPT 当负责人时生成提示词由你转给 Codex；X2 的专业子任务（数学符号、精细推导等）和 X3 用 GPT Work 极高，由你转交，不能拿 Codex 代替；X4 在派发时写明用 GPT Work 极高还是某个现有专门插件。凡需要你转交的，每个角色每轮也只发一条。
- **D8 复述每轮只开一个新对话，一次读完所有待读段落。** 这比每段换一个新读者的独立性弱，是为了让你只发一条而接受的取舍。
- **网页端打包放进 0.1**，沿用 thread handoff、thread instruction 已经测通的方法，不另造。
- **插件市场上限调到 12 个插件、32 个技能**，两个新插件直接进市场，旧插件一个不删。
- （默认）**状态全部存成仓库里的文件**，不建中央服务、不常驻后台。好处是简单、可追溯；代价是不能自动推送提醒，要你或负责人去读状态。
- （默认）**新流程只对你明确选用的任务生效**，已有任务不自动迁移。
- （默认）**只改错字一类的小修不需要你重新批准**，但每次都要事前告诉你、事后给差异，并重跑结构检查。凡是改变含义的修改，都要重新过关卡、重新请你批准。
- （默认）**状态文件损坏、恢复时对不上的记录怎么办：** 涉及冻结、批准、签发、撤回的交你决定；其余的一律当作没发生，标为作废、保留原始记录、需要时重新派发，并告诉新的接收者原来已经写过什么。另外两种情况也找你：原来已经写进仓库的内容和重做的工作互相冲突；重做会产生无法撤回的后果（付费、发布、发消息）。等你决定期间，只暂停受影响的那部分工作。
- （默认）**这个插件自己的实施由 GPT Work 极高担任 X1**，Claude 只负责机械地启动 X1 写在仓库里的 Codex 派发。插件本身的通用规则仍允许 Claude 或 GPT Pro 当负责人。
- （默认）**签发只有一次，覆盖整个冻结范围。** 不能拆成几块分别签发，也不能临时缩小承诺来交差；确实需要分批交付的，要在设计阶段就拆成几个任务，各自冻结、各自签发。冻结合同如果要求你亲自验收，签发前必须先拿到你的实际验收结果。签发之后如果出现可能推翻结论的新事实，X1 先暂停对外声明，再决定维持还是撤回整份签发。
- **被放弃的方案：** 每段换一个新读者做复述（需要你发几十条，已否决）；先只做直接安装包、以后再进市场（多一轮过渡，已否决）；网页端推迟到 0.2（你已测通，没必要推迟）。

## 3. 做完时你会看到什么，你自己怎么验

这是插件，做完后你会看到：

- **在 Codex 里：** 插件市场多出两个插件，各有一个执行技能，只接负责人明确派发的工作。没有派发时，它会说缺什么，不会自己动手。
- **在 Claude Code 和 GPT Work 里：** 告诉负责人“继续这个任务”，它读当前状态，给出下一步和完整提示词。
- **在 ChatGPT 网页端：** 上传插件包，新开一个对话，它能读规则、给出下一条提示词，并在有仓库连接时写回指定分支。它会如实说明自己不能运行本地脚本。

**你自己怎么验：** 拿一个公开、安全的示例任务，从需求开始走一遍：派设计 → 过四道关卡 → 你批准 → 交付 → 修一次验收程序 → 签发。中途故意制造几种错误，看它是否拦住：
- 拿过期的状态去派发；
- 验的是 A、交的是 B；
- 偷偷放松验收标准；
- 拿不到原始证据却想签发。

拦住了才算通过，出错时应该明确告诉你“无法判断”，而不是写成通过。

## 4. 验收器

一共 **68 个**，都是必须通过的。其中 55 个检查正常功能，13 个专门检查出错时的处理。按测的功能分成 6 类：

| 类别 | 个数 | 测什么 |
|---|---:|---|
| 任务状态与交接 | 8 | 一个任务只有一份当前状态；换人接手、写入中断、状态损坏后都能恢复，并且不会两人同时改；修订会事前、事后告诉你；三项衡量数据能从记录里重建 |
| 派发与提示词 | 3 | 按当前状态选对角色和档次；生成的提示词不依赖上下文，换一个新对话也能直接开工；某个角色用不了时如实报告，不让别的角色顶替自审 |
| 13 个角色各自的职责 | 15 | 每个角色（D1–D8、X1–X5）用对档次、只读该读的材料、交回该交的东西，不越权，例如设计者不能自己冻结、X5 只给意见不签发 |
| 从需求到冻结 | 18 | 澄清需求；四道关卡缺一不可，不能拿不同版本各过一项拼起来；冻结合同的九项都写清楚；冻结说明按固定格式，由 D6 核对；你没批准就不能冻结 |
| 从冻结到签发 | 13 | 修验收程序时不能改掉“什么算完成”；验收器要用正例、坏例、缺证据的例子校准过；签发的必须是当前最终成品；拿不到原始证据就是“无法判断”；签发后发现新问题能暂停、维持或撤回 |
| 打包与安装 | 11 | 规则只有一个来源，各端读到的是同一份；两个 Codex 包安装后入口正确、资源齐全；网页端包按上面三件事真实验收；市场预算调整到 12/32 且旧插件不受影响；下面的回归用例集全部通过 |

**这些验收器怎么跑：**
- **每一个都要有人发起一次。** 68 个验收器全部由负责人按授权发出一次完整派发，执行者留下证据，需要独立检查的由独立角色亲自读产物。没有一个是“跑个脚本自动打勾”就算完的。
- **49 个必须在真实环境里做：** 真实派发角色、真实的 Claude Code、GPT Work、ChatGPT 网页端或 Codex，看实际输出。例如跨端读同一份规则、Codex 安装后调用、网页端上传后新开对话、四道关卡真实跑一遍、交付时亲读证据、状态损坏后真实恢复。
- **17 个读源文件就能判断**（例如规则只有一个来源、记录格式是否对），1 个要看生成出来的包，1 个要看安装后的结果。
- **X5 专业判断：** 签发前对提示词质量、责任链这类没有标准答案的问题，由 X5 给意见，X1 最终决定。
- **需要你本人：** 批准冻结；授权费用或账号；状态恢复时遇到上面第 2 节列出的那几种冲突。

**回归用例集：一共 8 个，全部通过才算 0.1 做完。** 验收器管的是每个组件，回归用例管的是“整个东西做没做完”。每个用例一次输入、直接看结果，用公开的示例任务；能一起测的合在一个用例里，逐条判：

- **R1 给出下一步：** Claude Code 和 GPT Work 两边给出同一个正确下一步；复述只生成一条提示词（以前要你转交几十条）；给你看的文字没有未解释的英文。
- **R2 正确冻结：** 冻结说明按十节骨架写、正文无文件名（以前写成审计报告）；冻结记录身份一致。
- **R3 拒绝不合规的冻结：** 缺关卡、说明检查后又被改过，都要被拦住并说清原因。
- **R4 交付与签发：** 放宽验收标准被退回设计负责人；验 A 交 B 不签；缺原始证据记“无法判断”。
- **R5 执行者不自己拍板：** 遇到没写清的选择，停下列选项（以前会自己选）。
- **R6 状态恢复：** 状态文件损坏后按规则恢复。
- **R7 安装：** 原有 10 个插件、30 个技能都在；两个新插件装上后入口正确；网页端包完成三件事。
- **S1 冒烟：** 用三个现有插件各发一条日常请求，不会被自动拉进 Assurance 流程。

判定方式：能机械判断的用脚本；“有没有没解释的英文”“说明是否按骨架写”这类，由 X5 或你按事先写好的尺子读全文判断。开发中修完一处，只重跑没过的和受影响的用例；最终版本确定后再完整跑一遍。以后发现新的真实问题，只能追加用例，不能删改已有的。

## 5. 需要下载或安装的大件

**设计里没有记录任何一项的大小，所以现在不能说“没有超过 100 MB 的”。** 设计里写到要用的有：

- Python 3.10 或更新版本；
- 三个程序库：JSON 格式检查库 `jsonschema` 4.26.0，以及两个哈希规范化库（Python 的 `rfc8785`、JavaScript 的 `canonicalize`，版本实施时固定）；
- 固定版本的 Blueprint 检查器（你已有的仓库）；
- 这两个插件自己的包，以及网页端沿用的现有打包方法。

设计要求在 Claude Code、GPT Work、Codex 和 ChatGPT 网页端上实际运行，但没有记录你这些环境当前的安装情况。

**设计对此的规定：** 实施时第一次下载或安装任何依赖前，执行者先记录它的实际大小；单项超过 100 MB 的，先经你授权再下载。

## 6. 不能降级的

- 不能用“文件都在”、旧版本、同一个对话自己审自己、“缺证据就算过”来代替真实验收。
- 无法判断必须写成无法判断。
- 签发必须对应当前最终成品，旧安装包、验过的另一个版本都不行。
- 原有 10 个插件、30 个技能一个不删，也不能变差。
- 规则正文只有一个来源，Codex、GPT 和网页端都读这一份，不能各写一套。

## 7. 实现者可以自己定的

文件内部怎么写、脚本细节、模板措辞、测试怎么组织，以及设计里没有限定的其他普通实现细节。

## 8. 权限、费用、时间

- **只改 AI_Skills_Collection 仓库**，它是公开的，不放任何私有项目内容。
- **不改 Blueprint 仓库**，只按固定版本调用它的检查器。
- **不加外部服务，不加自动付费调用。** 如果要用付费模型，次数和预算要在第一次调用前另行请你授权。
- **时间：** 设计里没有规定工期。

## 9. 这次不做的

自动新开或恢复对话、自动发消息、后台定时运行、任务看板界面、中央数据库或服务、旧任务自动迁移。这些留到 0.2 以后，等真实任务证明需要时再加。
