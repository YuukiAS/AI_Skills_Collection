# 流程图第二版规格

依据同目录 `ASSURANCE_PROCESS_DRAFT_V2_20261109.md`。设计已定，执行者只按规格出图；做不到的地方停下说明。沿用第一版的工具（D2 + ELK、Noto Sans SC、导出 SVG 与 PNG）和源文件结构，在其上修改。

## 与第一版相比必须改的

1. **每个角色节点三行字：**
   - 第一行：编号和角色名，例如“D2 独立设计者 A”；
   - 第二行：档次与担任者，例如“高 · Claude / GPT 最高档”；
   - 第三行：线程规则，取“沿用”“新开”“每次新开”“在 D1 线程内”之一。
2. **两个负责人节点（D1、X1）** 加粗边框，放在各自容器顶部；副标题写“唯一负责人 · 一个线程用到底”。X1 第三行写“只统筹，不写代码”。
3. **独立设计者 D2、D3 都用“高”的颜色。** D3 为可选。
4. **专业验收 X4** 标为“执行端·高或专门插件”。
5. **D1 节点内加一行“规定验收器”；X3 节点内加一行“实现验收器 · 可提案”。**
6. **压缩空白：** 交接带变窄，只放冻结合同节点；图例改为底部一行横排；整体字号放大，使 PNG 在 100% 缩放下正文清楚可读。

## 节点

左容器“Design Assurance：设计到冻结”自上而下：

1. 用户提出任务；
2. D1 设计负责人（顶部）；
3. 澄清（Grill Me），标“在 D1 线程内”；
4. 并列 D2、D3（可选）、D4 现实核查（可选）；
5. 汇总（在 D1 线程内）；
6. 冻结关卡虚线框：D5 结构检查、D6 用户代理追问、D7 冷读、D8 读者复述（四项都必跑，实线）；
7. 菱形“全部通过？”；
8. 用户批准冻结。

中间交接带：冻结合同 = Blueprint 冻结版本（四项内容同第一版）。

右容器“Delivery Assurance：冻结到交付”自上而下：

1. X1 交付负责人（顶部）；
2. 并列 X2 实现者、X3 验收器实现者；
3. 运行冻结验收器；旁边诊断检查（可选，旁注“X1、X2、X3 随时可加，不算验收”）与隐藏用例（可选，旁注“X3 保管，实现者看不到”）；
4. X4 专业验收（可选）；
5. X5 独立裁判；
6. 菱形“全部通过？”；
7. 用户验收（可选）；
8. 已交付。

## 连线：线型表示必跑或可选，颜色表示流向

| 视觉 | 含义 |
|---|---|
| 实线 | 必跑 |
| 虚线 | 可选 |
| 深灰 | 正常流程 |
| 红色、粗 | 退回或补缺口 |
| 橙色 | 验收器提案（只有建议权） |
| 紫色 | 修订后的新版本 |
| 浅灰紫细线 | 交回证据，不转移负责权 |

可选节点的进出线都用虚线；可选节点本身边框也用虚线。

必须出现的回流：

- 冻结关卡“否” → 汇总：红色，标“补缺口”。
- 右侧“否，属实现问题” → X2：红色，标“返修”。
- X1 → D1：红色粗线，标“退回请求”，旁列四类原因。
- X3 → X1 → D1：橙色，标“验收器提案”；到 D1 的一段标“D1 决定是否采纳”。
- D1 → 冻结合同：紫色，标“小修订：新版本，只重跑结构检查”。
- D1 → 汇总：红色，标“大改：重新过关卡”。
- X4、X5 → X1：浅灰紫细线，标“只交证据”。
- **“告知用户”：** D1 发出的小修订与大改两条线上，各挂一个琥珀色小标签“动手前、完成后都告知用户”。

## 颜色（节点填充）
