## 3. 现有实现实际做了什么

- `docs/plugin-todos/reasoned-decision.md` 声明为规划中的独立 Marketplace 插件，尚未正式实现。
- `docs/design/reasoned-decision/REASONED_DECISION_V0_1_ARCHITECTURE_2026-11-05.md` 状态为 `DESIGN_CONVERGED_FOR_REVIEW`，生产状态为 `NOT IMPLEMENTED`。
- 设计把任务状态、判断、方案三层职责分开，并提出先调查、优先复用、只补真实缺口、验证后冻结推荐。
- 内部两个技能和状态入口属于该设计的约定；本基线未找到同名正式插件运行目录。
- `docs/design/reasoned-decision/evidence/` 保存真实对话失败、后续纠正与拟议回归，不是当前插件的自动测试结果。
- 本次没有运行决策插件、修改设计或重新执行这些设备任务。

## 4. 需要用户裁决的问题

| 问题 | 选项 A / B（各一句后果） |
| --- | --- |
| 首轮先证实哪种任务？ | A：先覆盖真实故障和产品选择，使用现有案例较易验证。 / B：同时覆盖复杂架构与科研判断，需要额外领域边界和独立案例。 |
| 调查成本怎么由用户控制？ | A：按可能改变选择的未知自动收敛，必要时说明未核实项。 / B：非简单任务先给调查预算选择，用户多一次参与但能控制等待。 |
| 多轮状态保留到哪里？ | A：先使用当前对话及已有任务文档，不增加存储。 / B：在用户指定的任务内留下简短可恢复记录，跨会话需核对其时效。 |
| 缺决定性图片、日志或现场观测时怎么办？ | A：交付条件性候选并明确缺哪条证据。 / B：先暂停推荐，请用户提供最小必要观测后再排序。 |
| 执行验证先覆盖到哪？ | A：插件给出最小验证要求，由原执行能力完成并回传。 / B：首轮即要求与执行能力连通，需同时验证交接与回传。 |
| 用户看到多少判断过程？ | A：先给推荐、关键理由和唯一剩余验证，详细证据按需查看。 / B：同时给紧凑候选比较，便于用户直接核对淘汰理由。 |

现有架构已有冻结声明；这些问题涉及首轮范围和使用方式，不是本包替用户重开三层架构。若 GPT Pro 认为需要推翻，必须指出具体新证据或冲突。

## 5. 给 GPT Pro 的已知约束

- **先搞清目标和现状，再调查现实已有办法，优先采用、组合、扩展；有证据证明剩余缺口才自建。** 出处：`docs/design/reasoned-decision/REASONED_DECISION_V0_1_ARCHITECTURE_2026-11-05.md` 第 2–8 节。
- **当前要求不能被旧历史覆盖，已关闭问题和已淘汰路线不能无依据复活。** 出处：同文件第 4、6 节；`docs/plugin-todos/reasoned-decision.md` 第 54–66、76–87 行。
- **用户追问或换模型本身不是改判证据。** 新证据、约束、选项或推理纠错只更新受影响部分；连续两次以上反转要收缩，不能继续整套重排。出处：权威架构第 6、17 节；待办第 99–126 行。
- **证据必须对应决定性变量和具体对象。** 几何问题要看形状，运行问题要看真实行为；标签和重量没有因果连接就不能替代直接证据。出处：待办第 47–52、129–158 行。
- **权限、中断、维护、用户时间和信任损耗都是成本。** 状态读取先查数据面，重置和升级不能抢在更小诊断前，已有能力不自动成为必须保留的需求。出处：待办第 13–24、41–44、61–73 行。
- **结论强度不得超过证据。** 局部原则不自动推出整体优劣；明确推荐可以来自取舍，不能伪装成科学定理。出处：待办第 161–184 行。
- **完成绑定用户真实终点。** 重复任务继承成功能力、本次目标随实际状态更新；用户已完成选择，没有失败、新约束或主动重开就结束。出处：待办第 76–87、161–184 行。
- **不能用漂亮措辞或状态标签冒充可靠判断。** 用户需要知道能否做到、为什么、还差什么，而非内部记录；无调查能力不能猜“没有现成方案”。出处：权威架构第 7、12–15 节。
- **既有设计明确不做独立搜索技能、隐藏数据库、常驻服务、默认多代理委员会或另一个工作流系统。** 出处：权威架构第 1、15 节。这些是当前设计约束；本轮未授予推翻它们的权力。
