## 5. 边界条目

本能力既要决定“该出现什么”，也会遇到“存留内容怎么表达”的交接；下表不把两者合并成同一职责。

| 条目 | 为什么同时涉及内容与表达 |
| --- | --- |
| C02、C12、C22 | 应先决定解释是否还有新增价值；保留的解释仍需自然连贯，不能只按字数删除。 |
| C03 | 先决定整块保留、压缩、降级或删除，再完成存留文字，最后核对重排后的作品。 |
| C04 | 先判断免责声明是否改变推断；值得留下的限制还须用适合专家读者的语言说明。 |
| C05、C10、C11 | 次级标签可能根本不该有；必要标签、状态与警告则需要清楚准确地写出。 |
| C06 | 首页放哪些概念、表格和对照属于内容组织；技术解释能否读懂属于表达。 |
| C07、C09、C26 | 具体核对内容是否保留取决于读者任务；压缩后的写法不能用抽象维护话语替代信息，也不能把整节删除缩成一句润色。 |
| C08 | 冗余文案能删除，但必要术语还可能不合中文读者习惯，需要产品文案和领域命名负责人处理。 |
| C13、C14、C15、C33 | 内容取舍、压缩与转图先确定可见范围，语言负责人再表达获准含义，不能用措辞偏好重定领域结论。 |
| C20、C21、C25 | 人要继续工作的信息应留下，但长流程契约应改写成可操作的少数步骤，不能只隐藏或照搬。 |
| C23、C24 | 先决定当前状态、历史和次级内容放哪里，再把主表面的当前动作和链接说明写清楚。 |
| C28、C29、C30、C31 | 无依据交互、整列解释或内部说明可能应整块移除；留下的数学、职责和必要要求仍要让人读懂。 |
| C17、C32、C34、C37 | 整件作品复审同时检查内容必要性和全文语言质量，漂亮的聊天汇报不能代替实际文档。 |

本轮未把历史包装方案变成新设计，也未把私有案例原件、专有术语或源材料中的私人定位复制进本文件。
