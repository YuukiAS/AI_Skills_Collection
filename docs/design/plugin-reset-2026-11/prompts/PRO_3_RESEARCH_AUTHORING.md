# GPT Pro 设计任务 3：research-authoring 插件 v0.1（在任务 2 设计之后发）

## 这个插件要解决什么
GPT/Codex 产出研究文档时，常交出一份内部工作报告：研究问题、方法怎么算、为什么做下一个实验都没讲明白；不同读者的材料混在一起；确认过的版本小修时被改坏。不同读者要求不同：给用户本人要让他看懂并能裁决；给导师要讲完整的故事；给学生的作业或讲义不讲无关的东西。

## 已定范围
- 本轮只覆盖近期这批待办；写论文、文献检索、引用核对相关条目（COVERAGE 中标为"暂不做"）不进入 v0.1，现有 `paper`、`litcite` 保持原样不动。
- 产出不只是 PDF，也包括直接推到 GitHub 的 Markdown；COVERAGE 中列出的其他产出形式，请判断哪些进 v0.1。
- **读者固定为 4 类（用户已裁决）**：① 用户本人；② 导师、组会听众、合作者和跨领域读者（同一类：要一个完整的研究故事）；③ 学生（作业、讲义，不讲无关内容）；④ 论文读者。COVERAGE 里的其他读者类型（教师/考官、审批者、实施者、QA/发布者等）**全部不需要**，相关条目在全覆盖表中标"不做"并给一句理由。
- skill 按这 4 类读者来拆（这是用户想要的切法）；同一类读者的不同产出形式（PDF、GitHub Markdown 等）在 skill 内部处理。论文读者这一类在架构中保留位置，但本轮不实现写论文和文献检索，现有 `paper`、`litcite` 不动。
- 必须调用任务 2 已定的 content-selection 与 clear-writing，不在本插件里重复它们的规则。research-authoring 自己负责研究文档的读者任务、论证/证据结构、文档家族与批准边界；content-selection 决定哪些内容值得进入成品并参与整件成品复审；clear-writing 负责存留内容如何讲清楚。

## 用户后续裁决（适用于本设计，优先于下文通用要求）
- **执行证据**：插件被调用时，回答必须附上一个文件（GPT 端）或推送一个文件（Codex 端），逐条写出"规则编号 → 成品中对应的原句/位置"，有改写时附改前→改后。未调用插件则不附任何东西。不设计每轮聊天的独立检查器，也不对每次产出另做独立复审。
- **v0.1 只搭架子 + 少量必要回归**：必要验收用 3–4 个真实回归案例即可，不要求"未见样本冻结""新旧入口对比""同一最终候选统一认证"这类重型关卡；大量回归放到后续版本。目标是尽快发出能用的 v0.1，不要像 assurance 那样反复卡关。
- **Codex 端定位**：Codex 端只负责渲染、机械检查（含通用验收器）、发布和回读；读者判断与写作在 GPT 端完成。
- 任务 2 设计书中的 `content-selection` 与 `clear-writing` 已基本确定，按其接口调用。

## 背景
用户长期使用 GPT（网页/Pro）和 Codex。两者最大的共同问题：不考虑读者，该讲的不讲、讲不清，堆审计和后台记录，小修时把已确认的好内容改坏。用户要的是**尽快有一个能用的 v0.1**，之后版本号慢慢往上加；**允许推翻现有实现重做**，不必追求一次完美。

## 设计必须包含（按此顺序，作为一份 Markdown 设计书）
1. **一页结论**：用户读完这一页就知道插件长什么样、v0.1 做什么不做什么。
2. **架构**：插件 → 拆成哪几个 skill；每个 skill 管什么、何时被用到（用户点名、别的插件调用、还是自动）；skill 之间、插件之间谁调用谁。
3. **GPT 端与 Codex 端分工**：按用户已冻结的边界设计。读者判断、研究叙事、内容组织与写作属于 GPT 端；Codex 端只负责渲染、机械检查（含通用验收器）、发布和回读。对每个 skill 写清两端如何交接，但不得重新扩大 Codex 的内容判断职责。
4. **全覆盖表**：COVERAGE 里的每个簇 → 由哪个 skill / 哪条规则处理；凡本轮不处理的条目，按行号列出并给一句理由。不得有既未处理也未说明的簇。
5. **必要验收检查**：v0.1 只要 3–4 个真实回归案例。每项：检查什么｜机械可判还是需模型/人判｜覆盖哪些条目｜在哪一端运行。其余候选检查列入"以后版本"。
6. **现有实现怎么处理**：每个现有 skill/脚本：保留、并入、改写或删除，各一句理由。
7. **v0.1 与之后版本**：v0.1 范围；0.2、0.3 大致补什么。
8. **需要用户裁决的问题**：不超过 6 个，每个给选项、各自后果和你的推荐。

## 写这份设计书本身的规则（它的读者是用户本人）
- 中文；英文只保留确切名称。先说结论，再说理由。
- 正文只写用户需要知道和决定的东西；证据、行号、推导放附录。
- 不写"不是 X 而是 Y"式套话、口号、免责尾巴；不要整页"已核对/已检查"类审计说明。
