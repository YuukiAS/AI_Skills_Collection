## 1. Why this TODO exists

A presentation workflow can appear to have a strong control plane while still self-certifying an unusable one.

The real STAT5060 recovery task produced the requested headline counts:

- 213 feedback records;
- 38 stable pages;
- 11 shared components;
- G00–G15;
- 12/12 malformed fixtures rejected.

However, independent review found that:

- raw feedback was not converted into specific executable guards;
- historical pages were mapped by unsafe physical-page heuristics;
- an authoritative field containing `(1 | child_id)` was truncated by naïve Markdown-table parsing;
- preflight counts and conflict values were hard-coded;
- component consumers were inferred by keywords and were incomplete;
- acceptance gates were copied as prose rather than encoded as executable contracts;
- several fixtures simply set a boolean saying a violation happened, so the test did not prove a detector could discover the violation.

The generic lesson is that **record counts, schema presence and fixture counts do not establish semantic fidelity or enforcement capability**.

## 2. Required architecture

### 2.1 Planner-authored structured semantic sources

The control plane must distinguish:

1. human-readable planning documents;
2. Planner-authored structured authority;
3. generated derivative registries;
4. independent validation outputs.

Do not regenerate structured truth by scraping a Markdown table when the table can contain pipes, code spans, formulas or multiline text.

Each structured source has an identity/hash and is not generated by the same parser used to validate its derivative.

### 2.2 Specific feedback guards

Every human-feedback item must retain raw provenance and also point to a specific guard:

```text
feedback_id
raw_comment
annotation_type
colour
source_artifact
source_page_or_region
stable_target_ids[]
guard_id
normalized_requirement
lifecycle_state
supersession_edges[]
verification_contract
evidence_required
```

A placeholder such as “preserve this feedback and prove the complaint absent” is invalid normalization.

### 2.3 Explicit artifact ancestry maps

Feedback mapping uses:

```text
(artifact_family, exact artifact identity, historical page/region)
    -> stable page/component target(s)
```

It must never assume that historical page 12 equals current page 12. Unknown mappings remain `UNMAPPED` and block editing.

### 2.4 Explicit page/component binding

Each page declares its shared-component bindings. Component consumers are the inverse of that matrix.

Keyword inference from prose fields is forbidden for authoritative bindings. It can only serve as a diagnostic hint.

### 2.5 Executable gate contracts

Each acceptance gate needs:

```text
gate_id
owner_stage
inputs
check_contract
depends_on[]
blocking
pass_condition
failure_code
evidence_outputs[]
fixture_ids[]
independent_judgment_protocol
```

A prose excerpt plus an ID is documentation, not executable gate encoding.

## 3. Real detector requirement

Malformed-fixture tests must mutate realistic inputs and exercise the production detector.

Invalid examples:

```json
{"human_locked_body_changed": true}
```

This only tests that a validator rejects a flag.

Required examples:

- alter an actual locked body-region hash or rendered crop and verify the lock comparator detects it;
- add a visible string to an actual copy registry/candidate manifest and verify exact-copy comparison fails;
- replace a page’s approved layout archetype and verify the page-plan validator detects it;
- mutate an actual figure-label inventory from `$\eta$` to `eta` and verify the label scanner fails;
- delete or remap a historical feedback target and verify authority coverage fails;
- corrupt a field containing a literal pipe and verify source-fidelity comparison fails;
- map a historical page to the wrong stable PageID and verify a known-failure replay detects it.

## 4. Independent validation

Generation and validation may not share the same lossy parser as their source of truth.

Minimum protections:

- field-level comparison against Planner-authored structured source records;
- valid-target parsing for page IDs, component IDs and gate IDs;
- lifecycle/supersession graph validation, including cycles and missing reciprocal edges;
- derived rather than hard-coded counts;
- source-file hash coverage for every mandatory authority;
- known-failure replay from actual historical regressions;
- bidirectional page/component binding checks.
