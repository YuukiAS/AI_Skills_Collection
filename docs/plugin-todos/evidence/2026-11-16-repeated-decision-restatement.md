# 真实负例：同一实施决定在一条回答中被反复重新宣布

scope: 只记录用户可见表达失败。具体键盘映射、Karabiner 版本、Acrobat 实现路线和设备状态属于项目上下文，不作为通用规则。

## 截图中可见原文

> 下一步就是直接做统一实施，不需要你裁决任何东西。我刚才那句“等你裁决”说错了；你已经把目标讲得很清楚：Keychron 本机要整体好用，Acrobat 的 `Ctrl+滚轮` 必须实现，不能因为当前证据不够就放弃。
>
> 我现在会把它收成一次实施任务：先按审计结论落地 Spaces、`Fn+F5`、Edge、AltTab/Spotlight；同时把 Acrobat `Ctrl+滚轮` 当成强制验收项，由 Codex 在实施前自动查清最小可行实现层，必要时升级现有组件或用现有能力做最窄范围转换，但不能把“做不到”当默认结论。
>
> 下一步不是停，也不是让你选方案。我来裁决，然后给 Mac mini Codex 一次实施任务。主体键盘已经有足够证据；Acrobat 也把目标固定为“`Ctrl+滚轮` 必须缩放”，不再讨论要不要做。
>
> 现在唯一需要我先定的是 Acrobat 用哪一层实现最稳。我已经确认当前 Karabiner 16.3.0 本身没有滚轮转换能力；官方滚轮转按键能力是在后续版本/测试线才加入。直接为了一个 Acrobat 功能把整套 Karabiner 升到测试线，会把已经稳定的 73/322 规则和后面的 UU 体系一起带进升级风险，所以我不会这么做。
>
> 你不用裁决，目标已经够明确了。下一步就是实施，不再停。我会把这一轮拆成“主体键盘 + Acrobat 强制能力”一起交给 Codex；你只需要最后做一次真人验收。
>
> Acrobat 这项我也直接定原则：`Ctrl+滚轮` 必须在 Acrobat 内缩放，普通滚轮仍滚动，其他应用不受影响。当前 Karabiner 16.3.0 没有稳定版滚轮转换能力，而官方文档确认后续版本才加入 `mouse_motion_and_wheel_to_key`；因此我不会为了这一个功能把整个 Karabiner 升到测试线。

## 实际问题

回答已经在第一段形成了明确决定：继续实施，用户无需继续裁决，Acrobat 的 `Ctrl+滚轮` 是强制目标。后文又两次重新宣布同一决定，并分别使用“下一步不是停，也不是让你选方案”和“你不用裁决，目标已经够明确了”重新开场。

问题因此不只是一句否定式表达。完整失败链是：

1. **同一决定被重复宣布。** 新段落看似继续推进，实际主要重复“继续实施 / 用户不用裁决 / Acrobat 必须做”。
2. **重复结论依赖否定式包装。** 每次重新宣布决定时，先排除“停”“让用户选”“不要做”等选项，增加阅读负担。
3. **元修正继续占正文。** “我刚才那句说错了”把模型自己的纠偏过程留在用户正文中；用户已经给出目标后，修正应直接体现在新的行动结论里。
4. **调查过程与最终决定交织。** 搜索和技术判断确实提供了新增信息，但新增信息没有替换旧结论，而是夹在多次相同结论之间。
5. **停止条件失效。** 一旦“继续实施、Acrobat 是强制目标、暂不升级 Karabiner 测试线”已经成立，后续只需补真正会改变实施路线的新证据，不需要再次宣布“下一步就是实施”。

## 可泛化结论

Clear Writing 对“重复”的判断应以**语义增量**为单位。段落措辞不同、搜索状态变化或增加新的强调词，不代表产生了新的读者信息。

当一个决定已经成立时，后续正文只有在以下内容之一发生变化时才重新提及该决定：

- 新证据改变了决定；
- 新证据改变了实施方式；
- 新条件改变了风险、责任或用户动作；
- 当前段落需要极短回指才能理解新增信息。

否则直接进入新增信息。

用户纠正模型的上一句时，新的回答应直接呈现修正后的当前状态；除非纠错历史本身会影响行动或责任，不把“我刚才说错了什么”作为正文内容继续展开。

## 与现有 TODO 的关系

本案例扩展了 2026-11-03 “下一步先做什么却用否定式依赖分析开场”以及 2026-10-31 “同一结论反复换角度重述”的已有记录。

新的可迁移证据是：**重复结论、否定式包装和元修正可以在同一条回答内连续叠加，即使模型已经拥有正确决定和新增技术证据。**

这属于 Clear Writing / response-clarity 的通用读者层问题。当前个性化候选可把它作为“否定句仍会成为默认组织方式”的基线证据，但不应因此把完整案例、具体坏句式或新的大段禁令写进长期个性化。
