# Task State Contract

两个技能在每次进入任务、收到新事实或工具结果、恢复任务及准备收尾时共同使用本约定。状态服务于下一步判断与动作，不要求把完整内部记录展示给用户。

## 状态字段

- `CURRENT_QUESTION`：本轮真正要解决的问题。
- `SUCCESS_CRITERION`：用户实际看到什么才算完成。
- `HARD_CONSTRAINTS`：用户当前明确要求及有效授权边界。
- `CONFIRMED_FACTS`：已核实事实，并保留对象、来源和时点。
- `COMPLETED_ACTIONS`：已经完成且无需重复的动作。
- `CLOSED_QUESTIONS`：已经解决或用户明确结束的问题。
- `ELIMINATED_ROUTES`：被约束或证据淘汰的路线及原因。
- `DO_NOT_REVIVE`：缺少相关新证据时不得恢复的问题和路线。
- `ACTIVE_UNKNOWNS`：仍可能改变选择、行动条件或结论强度的未知。

当前推荐及其关键前提随有关事实保留，供后续消息核对改判依据。

## 共同规则

- **TS-01 初始化。** 开始工作前恢复上述字段；缺少历史材料时先在当前对话、指定文件和可用工具中定位，只补问决定当前选择所需的最少事实。
- **TS-02 权威与时效。** 依次采用用户当前要求、当前真实系统或项目证据、当前冻结合同、当前权威资料、旧聊天或旧方案、社区经验和模型推断。旧材料保留为历史，不能自行升级成当前硬约束。
- **TS-03 消费完成状态。** 下一步必须跳过 `COMPLETED_ACTIONS`，遵守 `CLOSED_QUESTIONS`、`ELIMINATED_ROUTES` 和 `DO_NOT_REVIVE`。同一环境已经验证成功的能力继续沿用；新会话、版本号变化或用户追问本身不触发整套重新发现。
- **TS-04 保持整体目标。** 多设备、多角色或多入口任务先形成最小“场景 → 期望行为”对应关系。区分必须保留、可以取舍和偶然已有的能力，局部症状只能修改受影响场景。
- **TS-05 局部更新。** 新事实进入后，标明它更新的对象、变量和前提，只修改受影响的状态。更强实测取代旧规格时更新 `CONFIRMED_FACTS`，并保留相关淘汰理由。
- **TS-06 关键未知。** `ACTIVE_UNKNOWNS` 只保留会改变当前决定的事项。连续两次同类方案被推翻后，停止扩候选，优先裁决一个信息价值最高的未知；其余独立未知继续如实保留。
- **TS-07 技能交接。** `judgment-integrity` 交给 `solution-design` 的最小信息包括目标、成功条件、约束、有关事实、淘汰路线和待裁决未知；后者返回实际来源、候选与覆盖、未核实部分、最小验证和结果。
- **TS-08 完成与重开。** `SUCCESS_CRITERION` 成立后记录完成并停止展开。完成的选择只有在真实使用失败、相关事实变化或用户主动重开时恢复，且只恢复受影响部分。
- **TS-09 用户输出。** 默认向用户展示明确判断、必要理由、适用边界和确有必要的下一步；内部状态名称、完整搜索清单和全部淘汰过程按需留在执行证据或引用材料中。
