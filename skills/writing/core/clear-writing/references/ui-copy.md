# 界面文字

用于按钮、标签、空状态、加载状态、错误状态、成功状态、设置帮助、引导、权限、隐私、信任和地区化界面文字。产品与领域负责人提供真实状态和后果，Content Selection 决定文字是否出现及其层级，Clear Writing 完成获准文字。

**UI-01｜取得完整界面上下文。** 写作前确认界面表面、控件角色、产品状态、用户任务、操作后果或下一动作、相邻可见文案、目标地区、受保护含义、披露层级以及视口限制。缺少产品真值时交回产品负责人。

**UI-02｜先确认内容位置。** 文案数量、放置、层级、渐进披露和整块删留来自 Content Selection。发现重复整列、无依据引导或错层披露时，返回内容计划，避免靠改词掩盖结构问题。

**UI-03｜准确表达状态。** 区分未知、当前没有结果、尚未就绪和已经就绪；同时区分可用、不可用、待处理、失败、成功、可选和必需。界面文字应与实际产品状态一致。

**UI-04｜动作文字对应真实后果。** 按钮和链接使用清楚的动作词，说明必要的对象、可逆性和下一步。删除、公开、同步、付费、取消、保存和发送等动作不得弱化真实后果。

**UI-05｜状态信息帮助用户继续。** 空、加载、错误和成功状态说明发生了什么，以及用户当前能做什么。技术细节只有在支持用户判断或排障时进入可见文案。

**UI-06｜保护信任与必要披露。** 隐私、数据使用、保留、删除、权限、安全、价格、订阅、可见范围和资格条件保持完整。文案自然化不得改变这些事实。

**UI-07｜分别完成地区化表达。** `zh-Hans` 与 `zh-Hant-HK` 从同一受保护含义分别写作，使用各地区自然词汇和语气。字符转换不能替代地区化写作。产品名、功能名和必须匹配的政策词保持一致。

**UI-08｜保留可访问名称与必要单位。** 标签、输入说明、单位、操作条件、安全警告和辅助技术可访问名称具有独立作用时应保留。视觉布局已表达关系时，可以删减重复解释。

**UI-09｜检查整页节奏。** 结合相邻文字和实际界面检查重复、语气、层级和换行。单句合法仍可能在整页形成政策口吻或说明堆积；此时按责任返回 Content Selection 或产物负责人。

**UI-10｜只改获准范围。** 已经清楚且含义正确的文字可以保持。局部返修只改指定控件及受其影响的相邻文字，其他已接受区域继续保持。
