## 先判断页面，再处理措辞

审阅顺序为 Frontend Design → Product UI Copy → Frontend rendered acceptance。本次是有界文案评审，设计依据是捕获中的现有页面上下文，不引入新视觉方案或新测试样本。

共同的受保护含义包括：CUHK 在读学生及年满 18 岁的使用条件、身份自行声明、@Link 只验证邮箱控制权、独立学生项目身份、每轮主动报名、最多介绍一人、不保证结果、相片选填与审核限制、联系方式显示须双方明确同意。捕获中的陈述只作为待保真的产品表述，不等于其运行行为已获验证。

### 首页：先让人知道能做什么

范围：`/zh-Hans`、`/zh-Hant-HK`；依据：输入 03、08。

需要保留品牌、服务对象、当前开放状态、主要入口、四步流程、资料可见范围、资格和非官方披露，以及页脚入口。品牌是标题；“首批同学加入中／首批同學加入中”是状态徽标候选；“只开放注册／只開放註冊”是系统状态；“先把资料准备好／先把資料準備好”是行动提示；创建账户和查看流程是 CTA。文本抽取不能确定它们真实的字号和组件类型。

首段、状态区和流程引言都在重复“先填资料，轮次开放后再决定”。建议把当前状态与报名区别集中在 CTA 附近，流程区只解释步骤。“首批同学加入中”带招募口吻，也可能让人误以为已有真实加入数据；“不是刷资料……”在普通操作说明中变成口号。“清楚的边界”区不应再次承担报名结果解释。

简体的“为 CUHK 学生而设”“自主参加轮次”偏书面；香港繁体的“為……而設”可以自然保留，但“輪次”同样有系统术语感。两版均不能把“建立／创建账户”改成“立即配对”：注册不等于报名，更不等于获得介绍。捕获称两版注册路由均为 404，因此当前开放状态须交产品方确认。

### 如何运作：步骤要说明动作，披露要说明后果

范围：两种语言的 `/how-it-works`；依据：输入 04、09。

需要一个页面标题、四步说明、独立的双方同意说明、私隐限制和返回首页入口。导航中的同名链接应保留；正文疑似重复的“如何运作／如何運作”和品牌眉题可合并，不把浏览器标题误当成正文重复。步骤标题应说用户要做什么，“验证学生使用范围”却像系统任务名。“最多收到一位介绍”搭配生硬。

“私密、低频”是概括性描述，实际频率尚无日期或周期支持；正文的主动选择规则比这两个形容词更有用。尾段同时解释阶段、宣称首页会清楚展示状态、再次披露非官方身份，职责过多。应保留阶段区别与返回入口，把身份披露放入清楚的固定位置。

简体“认识偏好”、繁体“認識偏好”都不够具体，但不能擅自改成择偶条件，因为输入没有界定用途。香港版“電郵、相片、配對”自然；简体版“邮箱、照片、匹配”不应被统一替换。不同意的决定是否完全不可推断、能否撤回同意，现有材料不足以定稿。

### 隐私说明：读者需要资料处理事实

范围：两种语言的 `/privacy`；依据：输入 05、10。

需要一个标题、运营者身份、收集和使用类别、对他人的可见范围、第三方服务、删除与保留、查阅更正渠道。正文都是隐私披露，不能按营销文案压短。“第一批真实用户前的资料边界／第一批真實用戶前的資料邊界”是内部阶段标签，应从眉题移除；重复页面标题可合并。没有行动 CTA 的必要，联系邮箱应是可识别的求助入口。

“版本化……时间证据”“资格边界”“匹配输入”像工程或审计说明。“受保护的联系方式存储区”描述实现，却没有替用户解释谁可以访问。第三方服务商名称则有实际披露作用，应保留，不能一概当成技术泄漏删除。“不是法律意见／外部法律审批未完成”不宜靠润色变成已获认可的承诺。

简体使用“隐私、上传、邮箱”，香港版使用“私隱、上載、電郵”各有理由。香港版“信箱／郵箱／電郵”可按地址、收件设施、发送动作区分，不必机械统一。两版共同缺少明确保留期限、删除各阶段的后果和“安全的概括原因”的具体范围；这些交产品与隐私负责人确认。

### 使用条款：规则应能被用户理解和遵守

范围：两种语言的 `/terms`；依据：输入 06、11。

需要资格、行为规则、结果限制、内容责任、同意和联系方式、安全限制及账号处置后果。标题与“核心规则”等为层级标题，正文为法律或产品披露，页脚为导航；无需增设营销 CTA。“第一批真实用户前的使用边界／第一批真實用戶前的使用邊界”和重复标题可减去一层。

“系统按已冻结的产品合同……”直接把内部实现合同写给用户；“不降低质量边界”又没有可理解的标准。不能只换成“严格保障高质量配对”，那会扩大承诺。法律审批进度也不能由文案方隐藏或宣告完成。没有匹配的结果说明值得保留，其“有效”一词可以自然化，但不删后面的不保证结果条款。

简体“产品不是什么”、香港版“產品不是甚麼”都是反向定义，分类标题可更直接，但正式条款重组须保留规则。香港版“配對發布”与流程页“結果公布”表达不一致；先确认是否同一事件再统一。注册、报名、公布是否都处于暂停状态，以及账号移除是否等于删除资料，不能由措辞判断。

### 支持与安全：先帮助人找到合适渠道

范围：两种语言的 `/support`；依据：输入 07、12。

需要一个标题、登录后处理与无法登录时的联系路径、邮箱使用限制、举报与封锁后果、删除说明、紧急情况指引。它们分别承担支持指令、隐私披露和安全说明。连续“支持与安全／需要协助／支持与安全”信息增量很低，建议只留一个标题和简短导语。紧急指引应容易发现，不应仅被当成长文末尾补充；实际是否藏在首屏以下须看截图。

登录后优先使用产品内功能，在导语和删除段重复出现，可整理成同一处分流说明。“目前介绍相关页面”缺少能找到的入口名称；在没有登录态证据时不能编造按钮或路径。“删除会移除或解除使用”仍未解释用户实际后果，不应改成“彻底删除”。

简体“电邮、回报”可改为“发送邮件、反馈”；香港版“電郵、回報、支援”可以保留。“如果你已能登入”改成“如果你能登入”便足够，不必强行口语化。两版举报者保护的说法比隐私页更宽，需要共同确认边界。

## Product UI Copy 的有界交接

下表固定表面、角色与邻文，避免孤立美化句子。两种语言分别实现同一含义；没有视口尺寸，因此不制定虚假的字数上限。

| 表面与角色 | 用户任务、状态与下一步 | 邻文、受保护含义与披露层级 |
|---|---|---|
| 首页：状态、正文、CTA | 了解服务后决定是否建账户；输入声称只开放注册，404 使可用性未决 | 紧邻资格与流程；不得暗示自动报名或保证介绍；首页简要说明，详情另页 |
| 流程：步骤标题、正文、返回入口 | 理解填资料、主动报名、介绍和同意的区别 | 紧邻相片和联系资料限制；最多一人及双方同意不变；不能把邮箱验证写成学生身份认证 |
| 隐私：标题、资料处理披露、邮箱 | 判断如何处理资料并找到查阅更正渠道 | 保留第三方名称、用途、可见性和例外；不替换为“绝对安全”；不删法律限制 |
| 条款：标题与规则正文 | 理解资格、责任及违规后果 | 不保证介绍、回复或关系结果；内部合同语句先退回产品方；涉及义务的改写待确认 |
| 支持：分流、操作说明、安全披露 | 能登录时使用产品内功能，否则使用公开邮箱；紧急情况另寻即时帮助 | 保留邮箱处理人员、敏感资料禁发提醒和非紧急服务边界；入口名称未知时不杜撰 |

## 两种语言分别验收

**zh-Hans：**“创建账户、邮箱、照片、隐私、屏蔽”符合本版语境。支持页的“电邮、回报”与同站简体措辞不协调，可按 #30 调整。“最多收到一位介绍”“解除使用”分别是搭配问题与事实不清，不能都按语言错误处理。“微信号”是联系标识，不能为统一品牌而随意替换成仅指应用名称的 WeChat。

**zh-Hant-HK：**“建立帳戶、電郵、相片、私隱、支援、封鎖、舉報、上載”适合香港书面界面，不需要改成口语粤语。“為 CUHK 學生而設”可留；“自主參加輪次”“最多收到一位介紹”仍显生硬。“身份”无需机械改成其他地区常见写法。保留 WeChat、WhatsApp、CUHK @Link 和 Meet at CU / 中意 的精确身份。

两版的“轮次／輪次”“认识偏好／認識偏好”“校园节奏／校園節奏”需要结合功能定义处理。不能把繁体逐字转简体就视为自然，也不能为了自然自行把“交友”收窄为恋爱配对。语言切换按钮用目标语言“繁體／簡體”可以保留，但本次无法验证点击后的语言保持和路由。
