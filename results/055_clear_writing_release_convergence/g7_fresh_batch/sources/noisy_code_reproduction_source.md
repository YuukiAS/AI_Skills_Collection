## 真实内容从这里开始

我们在一个小型单细胞 RNA-seq 预处理脚本中发现，过滤阈值与批次标签的处理方式会显著影响后续聚类解释。这个脚本不是新算法，只是把公开数据下载后整理成统一的 AnnData 对象，方便比较不同批次校正方法。当前实验的目标是确认质控步骤是否稳定，而不是比较模型性能。

复现入口保留在项目根目录下：

```bash
python scripts/prepare_scrna.py \
  --input data/raw/pbmc_merged.h5ad \
  --output data/processed/pbmc_qc.h5ad \
  --min-genes 300 \
  --max-mito 0.18 \
  --batch-key donor_id
```

这些路径和参数应保留，因为它们说明了读者如何重现实验。相反，导出页面中的 `Home / Export / Print`、缓存路径 `/tmp/wiki-cache/render-42/` 和页面脚注不是实验条件，不能放进正式正文。脚本会先删除低质量细胞，再按 `donor_id` 写入批次标签；如果缺少 `donor_id`，脚本会停止，而不是自动把所有细胞当成同一批次。

我们目前只检查了 6 个供体、约 18,000 个细胞。结果显示，`--max-mito 0.18` 会比 `0.25` 多移除约 7% 的细胞，其中一半以上来自同一个供体。这个观察提示后续需要把供体差异和线粒体比例分开报告，不能直接说更严格阈值一定改善聚类。

待补充的工作是：在完整队列上重复阈值扫描，并把每个供体的保留细胞数写入补充表。当前文档不应把这一步写成已经完成，也不应把脚本路径误删为内部噪声。
