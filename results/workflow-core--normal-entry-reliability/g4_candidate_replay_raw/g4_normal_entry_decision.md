# G4 正常入口判断

默认 shell 找不到 `xelatex`，只能说明当前 `PATH` 未解析到该命令，不能据此宣布中文数学 PDF 渲染能力不可用。本场景应先走仓库和已安装专项技能提供的正常入口。

1. 先确认项目当前的渲染命令、模板、字体、资源包和渲染器约定；已有 canonical route 时优先使用它。
2. 使用 `render-chinese-math-pdf` 的环境探测入口：`python scripts/probe_pdf_render_env.py --root <project-root> --pretty`。这里的脚本路径应相对实际技能目录解析，不能假定项目根目录存在同名脚本。检查项目 `render_resources/chinese_math_pdf`、`CHINESE_MATH_PDF_RESOURCE_DIRS` 和 `.config/ai-skills/local-overrides.toml` 所指资源，再检查项目声明的环境或运行时。
3. 在当前 workspace-write 权限内运行适用的项目 runner、专项 probe 和本地验证。缺少默认 `PATH` 命令不构成请求提权、切换外部服务或绕过正常入口的理由。机器路径、模块名、临时包位置只记录为本次环境证据，不写成通用生产要求。

本场景不允许自动改用产物身份不同的 HTML/Chromium 方案。专项技能虽提供这种后备路线，但当前任务的产物约束仍然有效。自动恢复必须同时保持冻结效果、专业质量、验收证据强度、安全与隐私、产物身份和当前授权范围等价，且不得增加权限。任一维度变化或尚未确定，都应停止该替换，交由真正的任务负责人、Planner 或用户决定。未经明确批准，替代产物只能算诊断或降级结果，不能算原任务完成。

判断能力是否可用，需要区分以下证据：

| 证据 | 能支持的判断 |
| --- | --- |
| 裸 shell 中 `command -v xelatex` 失败 | 默认命令搜索路径未找到工具；尚不能判断正常入口是否可用。 |
| 专项 probe 找到项目或命名空间资源、可执行文件、字体或 TeX 包 | 存在候选路线；仍需确认可执行性及其是否满足渲染器约定。系统 `kpsewhich` 找不到 `xeCJK` 或 `ctex` 也不能否定可用的本地资源包。 |
| 正常 runner 在声明的环境中成功执行，并完成中文、公式样例验证 | 支持该环境具有相应渲染能力；样例成功不等于用户最终 PDF 已通过验收。 |
| 所有适用、合法且满足原约定的入口均有具体失败证据 | 才能报告当前环境与授权范围内能力不可用，并列明缺失命令、包、字体、资源或权限，以及已检查的路线。 |

实际渲染失败时，应依据首个有效错误做有限恢复，例如使用经探测确认的资源、生成合适的 header、将 TeX 缓存放入可写输出目录；不能盲目重跑或改变交付约定。最终 PDF 还需检查页数、中文和公式文本、表格内容、字体嵌入及页面图像，不能仅凭退出码或文件存在宣布完成。

本报告依据 `inputs/01-g4_capability_discovery_input.md`、当前安装的 workflow-core 和 `render-chinese-math-pdf` 技能作出路线判断。本次没有执行实际 PDF 渲染或环境 probe，因此不声称此机器已具备或缺失该能力；没有访问网络或执行发布命令。
