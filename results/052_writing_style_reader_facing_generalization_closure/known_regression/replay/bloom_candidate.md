# 布隆过滤器

布隆过滤器（Bloom Filter）用于判断一个元素是否属于某个集合，是伯顿·霍华德·布隆（Burton Howard Bloom）在1970年提出的一种空间效率很高的概率数据结构。{{sfnp|Bloom|1970}} 它通过一系列散列函数，把元素映射到二进制位数组中，不需要保存元素本身。

判断集合中是否存在某个元素，通常可以先保存所有元素，再通过比较来查找。链表、树和散列表（也叫哈希表）都采用这种思路，三者的检索时间复杂度分别为 `O(n)`、`O(log n)`（$O(\log n)$）和 `O(1)`。随着集合中的元素增多，存储需求也会增大，检索速度也会变慢。布隆过滤器在空间利用和查询时间上比一般算法更有优势，但这种方法可能产生假阳性，也就是误报；正常的添加和查询不会产生假阴性，也就是漏报。简单布隆过滤器还难以删除元素。

一个空布隆过滤器由长度为 `m` 的位数组组成，初始时每一位都是0。它使用 `k` 个不同的散列函数，每个函数都把元素映射到数组的 `m` 个位置之一。为达到最佳效果，这些函数应当均匀分布且相互独立。`k` 通常是一个较小的常数，取决于期望的假阳性率 `ε`；`m` 则与 `k` 和待添加的元素数量成正比。散列函数的个数也可记作 `K`，这里统一用 `k` 表示。

添加元素时，分别用 `k` 个散列函数计算它对应的 `k` 个数组位置，再把这些位置上的位全部设为1。查询时，对待查元素做同样的计算，检查得到的这些位置：只要有一位为0，就能确定该元素不在集合中，因为已经添加的元素会把对应位置全部设为1；如果所有位都是1，就只能判断该元素可能在集合中。这些位也可能是在添加其他元素时碰巧被设为1的，因此会产生假阳性。简单布隆过滤器无法区分这两种情况，但更先进的技术可以解决这一问题。

以集合 `{x, y, z}` 为例，位数组长度为 `m = 18`，散列函数个数为 `k = 3`。在示意图中，不同颜色的箭头表示各个元素经散列后对应的数组位置，箭头的个数表示散列函数的个数。元素 `w` 映射到的一个位置为0，因此可以确定它不属于集合 `{x, y, z}`。

当 `k` 较大时，设计 `k` 个不同且独立的散列函数可能很困难。一种办法是使用输出较宽的优质散列函数：它的不同位域之间应当几乎没有相关性，因此可以把输出切分成多个位域，用来得到多个“不同”的散列函数。另一种办法是给接受初始值的散列函数传入 `k` 个不同的初始值，例如 `0, 1, ..., k − 1`；也可以把这些值加入或追加到键中。

当 `m` 和/或 `k` 较大时，可以适当放宽散列函数之间的独立性要求，由此增加的假阳性率可以忽略不计。<ref>{{harvtxt|Dillinger|Manolios|2004a}}; {{harvtxt|Kirsch|Mitzenmacher|2006}}.</ref> {{harvtxt|Dillinger|Manolios|2004b}} 展示了用增强双重散列和三重散列导出 `k` 个索引的有效性。这两种方法都是双散列的变体，实际上是以两个或三个散列值作为种子的简单随机数生成器。

删除元素的问题出在多个元素可能共用同一个位。对于一个待删除元素，把它对应的 `k` 个位置中的任意一位清零，就足以让查询不再认定它存在；但这样也会让其他恰好映射到这一位的元素被判定为不存在。简单布隆过滤器无法知道哪些位还被其他已添加元素使用，因而无法确定哪些位可以清除。清零任何一位都可能引入假阴性，所以这种简单结构无法安全地移除元素。

可以用一个辅助布隆过滤器模拟一次性移除操作，把已移除的元素记录在这个“移除过滤器”中。不过，移除过滤器本身也可能产生假阳性；这些误报会在“原过滤器”和“移除过滤器”组成的联合结构中变成假阴性。这种方法也无法重新添加先前移除的元素，因为重新添加之前，必须先把它从移除过滤器中删掉，又回到了同一个删除难题。

与其他数据结构相比，布隆过滤器在空间和时间上都有很大优势，其存储空间以及插入、查询时间都是常数（`O(k)`）。散列函数之间没有相互依赖，便于用硬件并行实现。由于不必存储元素本身，它在某些保密要求非常严格的场合也有优势。

假阳性率是使用布隆过滤器时需要考虑的限制：存入的元素越多，假阳性率就越高。如果元素很少，使用散列表就足够了。围绕降低假阳性率，已有不少工作，也由此产生了许多布隆过滤器的变种。

当假阳性率过高时，可以重新生成过滤器。常见的情况是，所有待过滤的键都可以获取，但逐一枚举它们的成本较高，例如需要多次读取硬盘。因此，重新生成过滤器应当是相对少见的操作。
