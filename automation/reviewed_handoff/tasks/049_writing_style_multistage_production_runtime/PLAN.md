# 049 Writing Style — real multistage production runtime

## Objective and value

048 demonstrated that secure private transport, routing, fidelity checks and automated review can all PASS while the actual reader-facing report is still poor. The user rejected the delivered report immediately.

049 therefore fixes the production architecture, not the vocabulary list.

The task is complete only when:

1. the normal installed `writing-style` heavy route actually executes a meaning-first multistage runtime; and
2. the user's private Deep Research report, generated by that same runtime, is explicitly accepted for real research reading.

## Product preflight

### Final user experience

The user should be able to ask:

> 把这份中文科研长报告说人话，但不要改变事实、数字、公式、引用、比较、限制和结论强度。

and receive a document whose primary reading path explains the research question, evidence, implications and next experiment in natural Chinese.

The user must not need to know `scientific-rewrite`, Meaning Card, Fidelity Ledger or any internal pipeline term.

### Product failure even if tests PASS

The task is a failure if any of the following occur:

- the runtime still performs one whole-document rewrite call and merely cites the multistage workflow in documentation;
- the main reading path still follows repo-audit / implementation-contract / evidence-log structure when that structure is not itself the scientific argument;
- exact paths and identifiers are preserved only by leaving low-level trace material in the main narrative;
- automated readability review says PASS but the required human style smoke is rejected;
- the full private report is generated before style smoke acceptance;
- the final report is shorter only because information/caveats were dropped;
- the plugin works only in a benchmark helper or source-tree invocation, not the normal installed entrypoint.

## Alternatives considered

### Alternative A — keep 048 and add more Chinese rules

Rejected.

The active skills already contain the relevant positive-style rules. The failure was that production did not execute the documented architecture. More wording rules would increase instruction load without changing runtime behavior.

### Alternative B — keep one full-document model call but use a stronger prompt/model

Rejected as the primary architecture.

The failed artifact was already produced by a strong model with the full rule bundle. One-shot generation keeps the source's rhetorical skeleton as the dominant attractor and does not provide per-unit observable contracts.

### Alternative C — real multistage runtime with bounded unit generation

Selected.

This directly addresses the observed failure and matches the architecture already supported by prior research/047 evidence.

## Frozen architecture

### 1. One top-level plugin

Keep `writing-style` as the only user-facing plugin.

Internal ownership:

- `scientific-rewrite`: long-form meaning-first orchestration;
- `chinese-prose`: scene classification + positive Chinese language review + light polishing;
- `writing-fidelity`: literal and semantic fidelity audit;
- `scientific-prose`: English scientific prose, unchanged;
- `research-writing`: writing new reports from evidence, unchanged.

### 2. Scientific rewrite stage graph must execute

The heavy route must produce an observable stage receipt showing execution of:

```text
source
-> document map
-> argument units
-> Meaning Card + Fidelity Ledger per unit
-> source-to-card coverage check
-> positive transformation selection per unit
-> unit rewrite from meaning + original
-> literal verification
-> semantic audit
-> targeted repair
-> candidate-only reader review
-> final assembly / coherence check
```

The receipt may contain only non-sensitive counts/hashes/ids in public Git for private runs. Private intermediate text stays local or in the ephemeral runner.

A single whole-document model call is not valid evidence for this gate.

### 3. Bounded model responsibilities

Use model calls with different responsibilities rather than one universal prompt.

At minimum:

- **Map pass**: document purpose, audience, section roles, terminology, cross-section dependencies, major claims/caveats. No prose rewrite.
- **Meaning-card pass**: current argument unit only; extract claims/evidence/conditions/comparators/uncertainty/attribution/reader takeaway and literal inventory. No prose rewrite.
- **Writer pass**: current original unit + compact map + current Meaning Card + selected examples; generate only that unit.
- **Semantic audit pass**: source unit + candidate unit; classify preserved/narrowed/broadened/reversed/invented/omitted/reattributed.
- **Reader pass**: candidate text + audience questions only; it must not see the original source.

The exact number of calls may vary with document length, but responsibilities must remain separated.

### 4. Argument units

Do not split by fixed token count.

Default unit:

- one small subsection; or
- 2–5 tightly connected paragraphs.

Definitions, experimental conditions, results, caveats and conclusions must not be cut in the middle solely for length balancing.

### 5. Literal preservation gains location semantics

Extend the fidelity contract with two literal roles:

- `inline-critical`: exact material belongs in the main scientific explanation;
- `relocatable-trace`: exact material must remain in the complete deliverable but may move to a technical/evidence appendix.

Examples of likely relocatable trace include exact repository paths, checkpoint paths, exhaustive implementation identifiers and detailed audit records when they are evidence for a conclusion rather than the conclusion itself.

Relocation must never erase scientific meaning or attribution.

The final verifier must accept exact preservation across the whole deliverable, not require every trace token to remain in its original paragraph.

### 6. Reader Core + Technical Trace Appendix

When the source contains substantial implementation/audit trace material, the runtime may reorganize into:

```text
Reader Core
- research question
- evidence
- interpretation
- comparison
- uncertainty
- experiment / decision

Technical / Evidence Appendix
- exact paths / identifiers
- detailed audit provenance
- exhaustive engineering matrix
- other trace material required for full fidelity
```

This is not summarization. All material remains available; only its reading priority changes.

Do not force an appendix when the source does not need one.

### 7. Positive transformations must actually be selected

Keep the seed library small.

For each unit select 2–4 transformations based on:

- scene;
- discourse function;
- rewrite problem;
- fidelity risk;
- register.

Do not attach the entire seed library to every writer call.

Review the existing seed library for overly meta/template-like entries. Replace or revise only entries that demonstrably encourage workflow/audit prose. Do not expand into a broad corpus.

### 8. Reader review is separate from fidelity review

Source-aware fidelity review cannot also be the sole readability judge.

A candidate-only reader review must answer whether a technically capable reader unfamiliar with internal repo history can directly understand:

- what problem is being studied;
- what current evidence means;
- what remains uncertain;
- why the next comparison/experiment is needed;
- what decision follows.

Reader review may report awkward abstractions and unexplained technical labels, but it may not create a permanent blacklist.

### 9. Human style smoke is mandatory

Before full private generation, use the three frozen samples in `STYLE_SMOKE_MANIFEST.md`.

The implementation/runtime identity must be frozen before smoke generation.

Generate all three through the actual secure production path.

Stop at a human gate and ask for:

- `STYLE_ACCEPT`; or
- `STYLE_REJECT` with concrete feedback.

Do not continue to the full report without `STYLE_ACCEPT`.

If rejected, one bounded generic repair is allowed before re-running the same three smoke roles. Do not swap segments to chase a PASS.

### 10. Full private run only after style acceptance

After `STYLE_ACCEPT`:

- run the complete report with the same architecture/implementation identity;
- deterministic exact verification must pass for inline + relocatable literals;
- semantic critical violations must be zero;
- source-aware private fidelity review must PASS;
- candidate-only private reader review must PASS;
- render Markdown/PDF locally if the existing render route is available;
- user reads final artifact and decides `ACCEPT` or `REJECT`.

Automated PASS cannot override a final human rejection.

## Private runtime / Bridge Kit ownership

Keep the secure 048 transport architecture:

```text
local private plaintext
-> age encrypted input
-> GitHub Actions ephemeral decrypt
-> OpenAI Responses API, store=false
-> age encrypted output
-> local decrypt
```

Do not rebuild crypto or secret management in AI_Skills.

Writing-style owns the stage semantics. Bridge Kit owns secure transport/model-call infrastructure.

The preferred implementation is the smallest reusable Bridge Kit hook that allows a consumer-defined, SHA-bound multistage transform to run inside the ephemeral private workspace without committing intermediate plaintext.

Acceptable implementation forms include a generic staged-transform/driver hook if, after reading current Bridge Kit, that is the narrowest safe extension. The hook must remain domain-agnostic: scientific-writing prompts/stage definitions stay in AI_Skills.

Do not add unrelated Bridge Kit workflow/state machinery.

## Tests and evidence

### Mechanical / unit

At minimum verify:

- argument-unit preparation;
- per-unit example selection, not full-library injection;
- literal role classification and relocation-aware exact checking;
- source-to-card coverage contract;
- semantic audit status schema;
- light/heavy/fidelity routing;
- source/generated parity;
- no factual authority from examples;
- private staged transport leaves no plaintext in Git;
- stage identity is bound to implementation/instruction hashes.

### Production entrypoint

In an isolated/shadow normal Marketplace install, run a fresh ordinary-user heavy rewrite request.

Evidence must show that the installed route not only selects `scientific-rewrite`, but creates a real multistage stage receipt. A routing-only PASS is insufficient.

Also verify light polish and fidelity-only requests do not invoke the heavy runtime.

### Public regression

Use a small fixed public batch only. Do not broaden source scouting.

Require:

- at least one rewrite-needed public example showing a real multistage trace;
- at least one should-not-fix example.

### Private style smoke

Use the fixed three roles. User decision is required before full run.

## Red-team checks

Reviewer must actively check these failure paths:

- multistage stages exist only in docs/tests but production still calls one-shot transform;
- one huge prompt is split into several files but still one model call;
- Meaning Card is a lossy summary and writer no longer receives original source;
- entire seed library is still injected despite claiming retrieval;
- exact fidelity pushes paths/identifiers back into the reader core;
- reader review sees the source and becomes another fidelity review;
- trace appendix becomes a dumping ground that hides omitted scientific caveats;
- style smoke uses hand-edited outputs rather than the production runtime;
- human rejection is overridden by Terra/CI PASS;
- target-specific phrase replacements are hardcoded.

Any one of these is a Product blocker.
