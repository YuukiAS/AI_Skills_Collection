# Route C: Bridge Kit Distribution And Runtime Update

Use Route C for `update Bridge Kit` or when Route B release metadata declares Bridge impact.

The route is owned by `bridge-kit-maintainer`. This orchestrator only selects and sequences the route.

## Required Delegation

Delegate Bridge work to `bridge-kit-maintainer` for:

- resolved `ai-bridge` executable;
- `ai-bridge where` runtime/source root;
- package/runtime version check;
- real Bridge repo/main discovery;
- formal Bridge `release` ref resolution;
- canonical version-source reads;
- Bridge `AGENTS.md` owner locator consumption;
- newest provable formal release identification from version, changelog and
  closure evidence;
- release-state classification as `ALIGNED`, `LAGGING`,
  `AHEAD/INCONSISTENT`, or `FORMAL_RELEASE_NOT_PROVABLE`;
- canonical checkout fast-forward when ancestry and dirty ownership permit;
- editable package/entry point refresh from formal source;
- runtime path/version verification;
- Bridge release-ref production during formal Bridge release closure.

Delegate Host, Lite, Review, Control, Persistent Run, Human Gate, plugin replay and project-consumer implementation back to canonical `ai-bridge` commands.

Do not copy Bridge runtime logic into AI_Skills. Do not modify Bridge runtime source for a distribution/update orchestration task. If Bridge production behavior must change, stop and return to Planner/Critic.

Do not call a newer Bridge `main` latest merely because it is newer. Daily
`update Bridge Kit` is read-only with respect to Bridge `refs/heads/release`;
only formal Bridge producer closure may advance that ref.
